# Inkspell《墨法奇书》首个可玩验证版模块设计

文档类型：模块设计

来源 GDD：`GDD.md`

## 当前工程事实

- 当前安装 `com.july.arch` 0.5.0 与 Luban 1.1.1。实际 Framework 源码确认：System 由 `ArchContext` 定位并按注册顺序初始化，可通过 `IUpdatableSystem` 持续推进；Store 支持完整数据替换与 Dirty；Procedure 是可等待、可取消、可嵌套的一次性流程。下方角色规划以这些实际能力为准。
- `Assets/Game/Scripts/Runtime/HotUpdateRegistrar.cs` 是产品组合根。它已注册法术资产、法术合成、法术养成、法术生成、关卡推进和自动战斗能力；法术资产、法术生成和关卡推进 Store 已接入 `LocalFileSaveSystem`，自动战斗 Store 已注册但未持久化。
- `TimeSystem` 已注册；法术生成当前使用统一时间推进在线周期并记录离线起点。设备时间回拨、离线上限和关卡生成间隔的业务解释只归法术生成。
- Luban 作者源及 15 张已生成业务/框架表覆盖 UI、语言、法术定义/阶级/资产/战斗、合成、养成、生成、敌人、关卡战斗、关卡推进与关卡生成间隔。业务能力通过 `IConfigSystem` 读取所属表，不需要项目级 `ConfigSystem` 或 `ContentSystem` 聚合入口。
- 六个业务模块及主界面、详情、战场和离线收益表现接入均已存在。`StageChallengeProcedure` 真实编排“等待一次战斗→提交进度→胜负停顿”，符合 Procedure 成立条件；单次战斗的等待、取消和结果由 `AutoBattleSystem.RunChallengeAsync()` 内聚。
- 当前 `SpellSynthesisProcedure` 与 `OfflineGenerationProcedure` 只做同步计算和原子提交；目标设计把职责收回各自 System，不保留这两个 Procedure。当前 `AutoBattleStore` 的状态只服务于 `AutoBattleSystem` 且不持久化、不独立替换；目标设计把它收回 System 内部普通运行态。当前 `SpellAssetSystem` 大量转发 Store 读写；目标设计仅保留其配置接入、恢复后初始化和配置派生查询职责，其他模块可直接调用 Store 的公开语义能力。
- 当前 `SpellSnapshot` 以及 `BattleViewState`/子 View 类型都是只为普通读取而复制业务状态的中间层，不作为目标角色保留。后续实现使用 Store/System 实时状态的只读约定、真实业务结果或 WindowData；不因类型名是 `ViewState`、`ReadModel` 或其他名称而保留语义上的快照层。
- `Launch`、`Localization` 与 `UI` 目录承担启动流程或框架/表现集成，不拥有 Inkspell 业务决策，不列为业务模块。`OfflineRewardPresentationSystem` 只负责长期订阅已提交的离线收益事实并打开窗口，不参与收益计算或状态提交。

## 法术资产

### 负责

- 拥有玩家全部当前有效法术实例、魔法墨水余额和唯一标识分配状态的权威表示。
- 维持合成区与装备槽之间互斥的位置不变量，以及装备槽可空、单槽最多一个实例的不变量。
- 维持合成区容量；对未装备法术按 Luban 配置显示优先级与唯一标识生成稳定显示顺序，不持久化合成格显示索引。
- 完成锁定切换、装备和原子替换，并在空槽装备或其他变更释放合成区空位后发布稳定的容量变化事实。
- 维持魔法墨水不得低于零的状态不变量，为合成与养成提供同一 Store 内的法术/墨水原子变更。
- 为合成、养成与生成模块提供不暴露内部集合的语义更改能力，并且只在完整变更后发布业务事实。

### 明确不负责

- 不判定二合成功率、随机产物或失败墨水；这些归法术合成。
- 不解释升级成本、等级上限或墨水是否足够；这些业务判定归法术养成。
- 不计时产生法术，不拥有待领取队列；这些归法术生成。
- 不执行法术战斗行为、冷却或战场表现；这些归自动战斗。

### 权威状态与不变量

- 持久状态：法术实例种类、阶级、等级、位置、装备槽编号、锁定状态、唯一标识及其后续分配状态、魔法墨水；装备槽映射由这些实例的位置唯一导出，不允许两份可独立修改的真相。
- 合成区中的实例数不超过配置容量；已装备实例不占合成区容量。
- 装备替换在一次提交中使新法术进入目标槽、旧法术回到合成区，中间不暴露超容量或重复占位状态。
- 新进度初始资产严格采用 GDD 指定内容，不在模块设计中复制具体配置事实。
- 魔法墨水只能通过经授权的合成失败发放或单件升级扣除而变化，任何提交都不得将余额降至零以下。

### 稳定语义接口

- 查询指定法术、当前装备与魔法墨水，获取未装备法术的稳定排列结果和剩余容量；返回只读业务数据，外部不直接修改 Store Data。
- 接收法术生成模块移交的一阶法术，仅在有合成区容量时创建唯一实例。
- 处理锁定切换与从合成区到装备槽的装备/替换，以明确的成功或普通业务失败语义拒绝无效操作。
- 接受法术合成模块的一次经判定结算，在同一 Store 内原子消耗输入并创建成功产物或发放失败墨水；接受法术养成模块的经判定升级，原子扣除墨水并提升等级。

### 跨模块协作与事务编排

- 法术资产只对自身单 Store 内的位置、装备、锁定、实例与墨水变更原子提交；不编排合成随机结算或解释养成成本。
- 容量变更在资产状态完整提交后发布；法术生成模块作为唯一补入编排者消费该事实，资产模块不反向依赖生成模块。

### JulyArch 角色规划与成立依据

- 一个项目业务 Store：拥有法术实例、装备与魔法墨水的统一持久状态。它脱离单个 System 被法术合成、养成、生成和自动战斗等长期能力独立使用，并需要完整存档替换，因此满足 Store 成立条件。公开语义方法直接承担锁定、装备、接收生成产物、合成结算与升级提交，不再由 System 同名转发。
- 一个收窄后的项目业务 System：只负责持久化恢复完成后的新档初始化、容量与显示优先级的集中解释，以及依赖配置的未装备法术稳定排列查询。删除它会把恢复顺序、初始状态补充与配置排序知识泄漏给组合根或多个调用方；成立依据是初始化生命周期和集中业务解释，而不是读取配置本身。它不作为 Store 的统一门面。
- 普通类型：承担法术领域值、配置排序和 Store 内部派生索引；不建立 `XxxSnapshot` 读取层。
- 无 Procedure；锁定、装备、接收产物及 Store 内的合成/升级提交都是同步有界动作。

### 已确认扩展

无。只覆盖当前 GDD 已确认范围，不为未确认扩展预建职责。

## 法术合成

### 负责

- 对一次二合请求执行唯一的合法性判定，包括实例、阶级、锁定、位置、最高阶和已培养限制。
- 按输入阶级的 Luban 配置对合法请求进行一次独立随机判定，成功时抽取高一阶法术，失败时确定墨水奖励。
- 作为整个合成事务的唯一编排者，确保两张法术只在结果已确定时被消耗，失败墨水与消耗对外只显示为一次完整提交。
- 产生可区分的成功、转化为墨水或未消耗失败业务事实，供主界面播放反馈。

### 明确不负责

- 不拥有法术实例、装备槽、锁定状态或魔法墨水；这些统一归法术资产。
- 不判定法术升级成本或上限；这些归法术养成。
- 不负责合成动画、Tip 样式、拖拽命中或结果播放时序；这些属于 View 表现。

### 权威状态与不变量

无独立持久或长期运行时状态。每次合法请求的输入、随机结果与提交进度只属于当次有界流程；该模块不保存历史成功率、失败累计或保底状态。

### 稳定语义接口

- 接收两个玩家选定的法术实例标识，同步执行完整二合，向调用方返回是否已成功提交。
- 对普通业务失败提供稳定可区分的事实，如锁定、不同阶、已装备、最高阶或已培养；失败分支自身记录必要上下文，调用方不重复实现规则。

### 跨模块协作与事务编排

- 法术合成是二合事务的唯一编排者。它先通过法术资产读取业务事实并完成全部可恢复失败判定，然后请求法术资产在同一 Store 提交“消耗输入+创建成功产物”或“消耗输入+发放失败墨水”。
- 法术资产完整提交后才发布最终合成结果和容量变化事实；法术生成随后消费容量事实，保持“合成结果完成后再自动补入”。

### JulyArch 角色规划与成立依据

- 一个项目业务 System：作为二合的长期稳定业务入口，同步完成合法性判定、配置解释、随机结算、法术资产单 Store 完整提交与失败语义。删除它会迫使 Window 或其他调用方掌握全部限制、随机池解释和提交顺序，因此不是 Store 转发。
- 无 Store；模块没有 GDD 允许的历史或保底状态。
- 无 Procedure；一次合成没有等待、跨帧、嵌套或可取消流程价值。当前同步 `SpellSynthesisProcedure` 的职责应收回 System，不能只因现有接口返回异步类型而保留 Procedure。

### 已确认扩展

无。不为 GDD 的非目标预建职责。

## 法术养成

### 负责

- 拥有单件法术培养的成本、上限、成长与成败决策，使用法术资产的权威墨水和法术状态。
- 解释 Luban 中由法术阶级、当前等级、等级上限和成长值共同决定的升级规则。
- 解释 GDD 与 Luban 定义的成长曲线、升级成本和主要数值变化。
- 对一张指定法术执行单件升级，确保墨水扣除与法术等级变更对外只显示为一次完整提交。
- 产生墨水、等级和主要数值变化的业务事实，供法术资产重排、战斗下次施法和 View 反馈消费。

### 明确不负责

- 不拥有法术实例的种类、阶级、等级、位置、锁定状态或魔法墨水余额；这些统一归法术资产。
- 不使用墨水影响合成成功率，不处理培养返还、重置或降级。
- 不执行法术战斗效果，不追溯改写已发起的施法。

### 权威状态与不变量

无独立持久或长期运行时状态。魔法墨水与法术等级位于法术资产的同一 Store；法术养成独立拥有升级判定，不复制这些状态。升级成功与失败必须维持 GDD 指定的资产不变量，具体等级和数值事实仍以 GDD 与 Luban 为准。

### 稳定语义接口

- 查询当前墨水和指定法术的升级所需成本、上限与成长后数值。
- 对指定法术发起升级，成功时返回已完整提交的资源、等级和主要数值变化，失败时返回墨水不足或已满级事实且不消耗状态。

### 跨模块协作与事务编排

- 法术养成是单件升级事务的唯一编排者。它读取法术资产事实和 Luban 成本/成长，先完成全部可恢复失败判定，再请求法术资产在同一 Store 内原子扣除墨水并提升指定法术等级，完成后才发布升级结果。
- 合成失败中的墨水奖励数量和发放均由法术合成通过法术资产的原子结算完成；法术养成不介入合成事务，也不依赖法术合成。

### JulyArch 角色规划与成立依据

- 无 Store；模块不复制魔法墨水或法术等级状态。
- 一个项目业务 System：提供升级信息查询与单件升级的长期稳定入口，集中解释阶级/等级成本、成长倍率、满级与墨水不足规则，并编排法术资产原子提交。删除它会把配置解释和失败判定散落到 Window 或资产 Store，因而不是读写转发。
- 当前不需要 Procedure；所有可恢复失败在提交前完成判定，最终变更是法术资产单 Store 内的同步原子操作。

### 已确认扩展

无。不为 GDD 的非目标预建职责。

## 法术生成

### 负责

- 使用框架时间能力和 Luban 配置维持在线生成周期，每次到期从开放法术池按权重产生一阶法术。
- 拥有待领取法术，保证合成区满时只停止补入而不停止有效生成。
- 作为待领取自动补入的唯一编排者，在法术资产有空位时将待领取产物移交为真实法术实例。
- 记录进入后台或退出时间，再次进入时根据当时有效间隔、离线上限与合法时长计算新产物，先完整计入待领取并执行可完成的自动补入，再产生离线收益事实。
- 根据关卡推进公布的当前最高关，唯一解释该关对应的生成间隔并应用最小值边界。

### 明确不负责

- 不拥有已进入合成区或装备槽的法术实例；这些归法术资产。
- 不根据战斗过程、配装、合成或升级附加其他效率公式。
- 不进行离线战斗、关卡胜负或关卡进度提交。
- 不把待领取暴露为第二个可操作背包。

### 权威状态与不变量

- 持久状态：待领取法术、当前生成周期所需时间状态、当前生效生成间隔、最后进入后台或退出的时间。
- 待领取只能由成功的在线/离线生成增加，或在法术资产确认接收后减少；不因合成区无容量而删除。
- 离线可计入时长不小于零、不大于配置上限；离线结算不改变任何战斗状态。
- 当前间隔只是关卡进度配置的解释结果，不由其他模块直接写入，且不小于配置最小间隔。

### 稳定语义接口

- 查询待领取数量、当前生成进度和生效间隔。
- 在前台时按实际经过时间推进生成，在进入后台/退出时记录起点，在回到前台/启动时同步结算一次有上限的离线收益。
- 在自身生成或法术资产容量变化后尝试自动补入，并只在法术资产成功接收后提交待领取减少。

### 跨模块协作与事务编排

- 法术生成是“待领取→合成区”事务的唯一编排者。它查询法术资产容量，请求创建一个法术实例，只在法术资产确认后才从待领取移除对应产物。
- 法术生成读取关卡推进发布的进度事实并更新生效间隔；关卡推进不直接写生成状态，因而不形成循环依赖。
- 离线结算先完整增加待领取并执行可完成的自动补入，再产生包含合法时长、产生数和补入数的可展示收益事实；View 只在提交完成后展示，不自行计算、修改或回滚收益。

### JulyArch 角色规划与成立依据

- 一个项目业务 Store：拥有待领取、生成周期和离线时间的持久状态。该状态需要跨启动恢复与完整替换，因此脱离单个 System 生命周期成立；WindowData 读取不作为 Store 的成立依据。
- 一个项目业务 System：作为在线推进、前后台生命周期订阅、离线结算与自动补入的长期能力，由 JulyArch 每帧驱动并使用时间、配置、关卡进度与法术资产。删除它会把时间推进、焦点事件、队列移交顺序和跨状态提交知识泄漏给启动流程或 View。
- 无 Procedure；离线结算在该 System 内同步完成计算、待领取提交和可完成的自动补入，不等待表现，也不跨帧决定业务结果。当前 `OfflineGenerationProcedure` 应收回 System；收益窗口只消费已提交结果。

### 已确认扩展

无。只覆盖当前 GDD 已确认范围，不为非目标预建职责。

## 关卡推进

### 负责

- 拥有玩家已到达的当前最高关卡，初始为第 1 关且不超过 Luban 配置的最大关。
- 作为连续自动推关的唯一编排者，对当前关发起一次有界自动战斗，消费其唯一胜负结果，然后按胜利 1 秒、失败 2 秒的停顿规则发起下一次。
- 胜利时在未达最大关的情况下将进度提交为下一关；失败或最大关胜利时保持进度并重试/重复当前关。
- 在进度确实增长后发布关卡进度事实，供法术生成更新挂机效率与 View 更新关卡显示。

### 明确不负责

- 不模拟敌人、魔法书、法术冷却、弹道或效果；这些归自动战斗。
- 不解释关卡进度对生成间隔的具体数值影响；这些归法术生成。
- 不保存关内已消灭敌人、当前生命或其他临时挑战状态。
- 不提供选关、回退、跳关或手动开战。

### 权威状态与不变量

- 持久状态：当前最高关卡。
- 关卡从第 1 关开始，只能在当前关胜利后增加一关，并且不超过配置最大关。
- 一次挑战只能提交一个最终结果；进度变更后才发布进度事实。

### 稳定语义接口

- 查询当前最高关卡，供生成间隔、存档显示和主界面使用。
- 启动当前关的一次新挑战，对其胜利或失败进行唯一提交，再产生关卡增长或原关重试的业务事实。

### 跨模块协作与事务编排

- 关卡推进是“开始挑战→等待胜负→提交进度→开始下一次”的唯一编排者。它把当前关标识与关卡配置交给自动战斗，自动战斗只返回当次结果，不反向修改关卡 Store。
- 进度增长事实由法术生成消费；关卡推进不调用法术生成，去除返向依赖。

### JulyArch 角色规划与成立依据

- 一个项目业务 Store：拥有当前最高关卡的持久状态及其单向推进语义。它需要跨启动恢复和完整替换，并被连续挑战与法术生成长期能力独立使用，因此满足 Store 成立条件；WindowData 读取不作为 Store 的成立依据。
- 一个项目业务 System：拥有连续挑战循环、启动/关闭与取消生命周期，并作为稳定的关卡能力入口。删除它会把“重复读取当前关→运行挑战→衔接下一轮”的长期控制泄漏给启动流程。
- 每次关卡挑战使用由 System 创建和运行的 Procedure：它真实等待自动战斗结果，再提交胜利进度并等待胜负停顿，可被关卡循环取消，满足等待、嵌套和可取消条件。

### 已确认扩展

无。只覆盖当前 GDD 已确认范围，不为非目标预建职责。

## 自动战斗

### 负责

- 从关卡推进接收一个指定关卡的新挑战，按 Luban 编队、敌人、魔法书与时序配置初始化临时战场。
- 拥有魔法书生命与护盾、敌人生命/位置/状态、法术冷却、已发出攻击与效果等当次挑战权威数据；Book、敌人集合和冷却集合各自封装局部规则。
- 按配置时机生成敌人并推进单路径移动、接敌后攻击、护盾先于生命吸收伤害、敌人死亡与临时减速。
- 对每个装备槽独立推进冷却，在满足时机时重新读取当前装备法术及最新等级，以最近合法目标执行火球、雷链、冰环或护盾。
- 按 GDD 的同时结算优先级将一次挑战最终化为唯一胜利或失败结果，不自行更改关卡进度。

### 明确不负责

- 不拥有玩家持久法术、装备关系或等级；它在每次施法发起时读取法术资产的最新事实。
- 不修改当前最高关卡、生成效率、待领取或魔法墨水。
- 不在后台或离线时继续模拟战斗。
- 不决定战场美术、弹道动画、受击表现或 UI 反馈。

### 权威状态与不变量

- 模块内部非持久运行态：`BattleRunId` 标识每一次战斗尝试，重试同一关时也会变化；`StageId` 标识稳定的关卡配置。其余状态包括魔法书生命/护盾、场上敌人及其生命/位置/效果、出生进度、槽位冷却、已发攻击与当次结果。它们由 `BattleSimulation` 持有，只服务于自动战斗能力，不脱离该模块共享、替换或持久化。
- 新挑战始终清除上次敌人、临时效果、弹道和冷却，恢复魔法书初始生命并从关卡编队起点开始。
- 已发起的攻击保留发起时所需的战斗参数；之后的装备或等级变化只影响下一次合法施法。
- 已死亡的最后敌人不再在同一结算时机攻击；关卡已无存活敌人时胜利优先于魔法书死亡判定。

### 稳定语义接口

- 对指定关卡开始一次全新挑战，在前台时推进当次战斗，并最终只产生一个胜利或失败结果。
- 向 WindowData 提供当前 `BattleRun` 的实时只读访问；WindowData 直接把魔法书、敌人、冷却、攻击、效果和挑战结果转换为战场显示输入。中间不再复制为额外读取模型，View 也不直接修改 System 内部运行数据。

### 跨模块协作与事务编排

- 自动战斗只编排单次挑战内部的敌人、施法与结算步骤。关卡推进是跨挑战循环的唯一编排者，因此自动战斗不读取或修改关卡 Store，也不自行开始下一关。
- 每次到达合法施法时机时，自动战斗通过法术资产的只读稳定能力获取当前槽位法术，不缓存为可被换装/升级追溯修改的第二份法术状态。

### JulyArch 角色规划与成立依据

- 无 Store：当次挑战状态只由自动战斗模块的逐帧能力使用，随 `AutoBattleSystem` 生命周期存在，不参与持久化、完整替换，也没有其他长期能力需要独立共享。当前 `AutoBattleStore` 应收回为模块内部普通运行态；WindowData 按只读约定经 System 读取该实时状态，不因此建立 Store 或读取快照。
- 一个项目业务 System：作为 JulyArch 接入与编排者，负责挑战的异步生命周期、逐帧触发、事件发布及唯一完成通知；生成、移动、攻击、施法、效果与胜负优先级由内部普通类型 `BattleSimulation` 隐藏。删除这层编排会把框架生命周期和完成协议泄漏给关卡推进或 View。
- 无模块内 Procedure：单次战斗只是 `AutoBattleSystem` 自身的可等待长期能力，由 System 内部完成源衔接逐帧更新与唯一结果；不用具体 Procedure 实例充当并发锁或回调容器。
- 普通类型：`BattleSimulation` 以 `Begin/Advance/Stop` 的窄接口隐藏配置解释、敌人生成和跨对象结算顺序，并拥有当前 `BattleRun`；BattleRun 组合 BattleBook、EnemyRoster、BattleEnemy、SpellCooldownSet、SpellSlotCooldown、BattleAttack 和 BattleEffect。这些类型不需要 JulyArch 定位，`AutoBattleSystem` 不掌握具体战斗规则。

### 已确认扩展

无。只覆盖当前 GDD 已确认范围，不为非目标预建职责。

## 全局依赖与集成关系

```text
主界面 Window → 法术资产 / 法术合成 / 法术养成

主界面 WindowData → 法术资产 / 法术生成 / 关卡推进 / 自动战斗

战场与合成区 GameView ← 主界面 WindowData

法术合成 → 法术资产

法术养成 → 法术资产

法术生成 → 法术资产
             → 关卡推进

关卡推进 → 自动战斗

自动战斗 → 法术资产
```

- 上述业务依赖是单向无环的。容量变化、关卡进度、法术等级/装备变化等反向通知通过只读查询或最小业务事实完成，不让被依赖模块调用上层模块。
- 合成、升级、待领取补入和关卡挑战分别只有一个编排者；Window/GameView 只提交玩家意图和渲染 WindowData，不掌握跨模块调用顺序。
- 目标角色中只有法术资产、法术生成和关卡推进 Store，并全部参与本地持久化；法术合成、法术养成与自动战斗没有 Store。自动战斗状态由模块内部 `BattleSimulation` 普通类型拥有。组合根集中声明业务角色和持久化边界，并依赖现有 `LocalFileSaveSystem`、`JsonSerializeSystem` 与 `NoEncryptionSystem`。
- 法术、合成/墨水、生成、关卡/敌人与战斗数值属于 Luban 静态策划事实；实际承担配置读取的业务代码通过现有 `IConfigSystem` 获取所需表，不因读取配置额外创建 System，不在 Store 中复制配置，也不增设 `ConfigSystem`/`ContentSystem` 类产品模块。
- 存档恢复后，由法术生成先独立完成离线结算与自动补入，再由 View 展示已提交结果；关闭展示不影响生成状态。战斗仍从持久化的当前关起点开始，且只有生成模块使用离线时间。
- 主界面的 WindowData 是唯一显示输入，首屏从各模块的只读能力组装展示数据，后续可按业务事实刷新；它不修改 Store、不导航、不运行 Procedure。拖拽影子、动画进度、按压与当前播放位置等保持在 Window/GameView 的纯表现状态中。
- 主界面 Window 将锁定、装备等单 Store 同步意图交给法术资产 Store，将合成与升级意图交给对应 System；拖拽到空格或非法目标只恢复表现，不发起状态写入。离线收益展示适配只订阅已提交事实，窗口关闭不修改或回滚收益。
- 当前源码中的多余角色与读取包装是后续 MDD 的迁移事实：收回 `AutoBattleStore`、`SpellSynthesisProcedure`、`OfflineGenerationProcedure`、`SpellSnapshot`、`BattleViewState` 及其子 View 类型，并收窄 `SpellAssetSystem`。本次模块设计不修改代码，也不预先拆分实施切片。
