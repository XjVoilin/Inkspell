# M002 法术资产权威状态

文档类型：MDD

- 来源模块设计：`../模块设计.md`
- 来源 GDD：`../GDD.md`

## 目标与边界

创建法术资产唯一持久 Store，维护全部有效实例、位置、装备槽映射、锁定、唯一标识分配与魔法墨水，并提供同一 Store 内的原子修改。它不解释合成概率、升级成本或生成计时。

## 对应模块设计

- 所属模块：法术资产；落实该模块唯一 Store 规划。
- 权威状态与资产模块章节完全一致；装备槽映射只由实例位置导出，不保存第二份可写真相。
- 所有修改先完成再发布业务事件和 `MarkDirty()`。

## 对应 GDD 内容

对应 §7.1、§7.4、§9、§11.1、§12.1、§14.1、§20.2，以及 §14.3 第 5 条的资产提交先于自动补入。

- `Assets/Game/Scripts/Runtime/Modules/SpellAssets/SpellAssetEvents.cs`：资产整体变化与容量增加的最小业务事实。

## 角色与职责

| 类型 | 所属模块 | JulyArch 角色 | 职责 | 必要协作 |
|---|---|---|---|---|
| `SpellAssetStoreData` | 法术资产 | Store Data | 保存初始化标记、下一实例 ID、墨水和实例集合 | JSON 序列化 |
| `SpellAssetStore` | 法术资产 | Store | 维护资产不变量并原子修改 | `StoreBase<TData>`、M003 |
| `SpellAssetsChangedEvent` | 法术资产 | 业务事实 | 通知只读数据刷新，并标明容量是否增加 | 生成与 View |

## 状态与数据

- `SpellAssetStoreData` 公共可序列化字段：`bool Initialized`、`long NextInstanceId`、`int MagicInk`、`List<SpellInstanceState> Spells`。
- `SpellInstanceState` 字段：`long InstanceId`、`SpellType Type`、`int Tier`、`int Level`、`SpellLocation Location`、`int EquipmentSlot`、`bool IsLocked`。
- `Location == SpellLocation.CraftingArea` 时 `EquipmentSlot=-1`；装备实例使用 `SpellLocation.EquipmentSlot` 与 `0—3` 槽位编号，实际上限读取 `TbSpellAssetRule.EquipmentSlotCount`。
- 合成区占用数、稳定显示顺序和装备槽映射均为派生值；`OnDataReplaced()` 只重建 Store 自身索引，不复检完整状态。
- M003 的 `SpellAssetSystem.OnInitializeAsync()` 读取 `TbSpellAssetRule` 后调用 Store 的 `Initialize(TbSpellAssetRule rule)`；Store 在该调用中记住容量与槽位边界，并且仅在 `Initialized == false` 时一次建立新进度，避免把合法空合成区误判成未初始化。

## 行为与公开能力

跨模块不直接调用 Store 修改方法；这些方法为 `internal`，由 M003 的具体 System 暴露稳定能力。Store 本身唯一公开类型契约为：

| 类型 | 准确公开签名 | 语义 | 返回与失败处理 |
|---|---|---|---|
| `SpellAssetStore` | `public sealed class SpellAssetStore : StoreBase<SpellAssetStoreData>` | 注册并持有资产状态 | 完整替换沿用继承的 `GetData()`/`ReplaceData()` |
| `SpellAssetsChangedEvent` | `public SpellAssetsChangedEvent(bool capacityIncreased)` | 构造资产完整提交后的变化事实 | 只由资产 Store/System 发布 |
| `SpellAssetsChangedEvent` | `public bool CapacityIncreased { get; }` | 表明本次提交是否释放了合成区容量 | 法术生成只在 `true` 时尝试补入；其他消费者可直接刷新 |

Store 与同模块 M003 System 之间的 `internal` 契约固定为：

| 类型 | 准确模块内签名 | 语义 |
|---|---|---|
| `SpellAssetStore` | `internal void Initialize(TbSpellAssetRule rule)` | 接收已加载的资产规则，仅在未初始化时建立新进度 |
| `SpellAssetStore` | `internal int MagicInk { get; }`、`internal int CraftingCapacity { get; }`、`internal int RemainingCraftingCapacity { get; }` | 为资产 System 提供不暴露 Store Data 的只读事实 |
| `SpellAssetStore` | `internal List<SpellInfo> GetCraftingAreaSpells()`、`internal SpellInfo? GetSpell(long instanceId)`、`internal SpellInfo? GetEquippedSpell(int equipmentSlot)` | 转换为只读业务值；稳定排序仍由 M003 System 根据配置完成 |
| `SpellAssetStore` | `internal bool TrySetLocked(long instanceId, bool locked)`、`internal bool TryEquip(long instanceId, int equipmentSlot)` | 完成锁定与装备/替换的原子修改 |
| `SpellAssetStore` | `internal bool TryReceiveGeneratedSpell(SpellType type)` | 有合成区容量时创建一阶 1 级实例 |
| `SpellAssetStore` | `internal bool TryCommitSynthesisSuccess(long firstId, long secondId, SpellType resultType, int resultTier)`、`internal bool TryCommitSynthesisFailure(long firstId, long secondId, int inkReward)` | 完成两种合成结算的单 Store 原子提交 |
| `SpellAssetStore` | `internal bool TryCommitUpgrade(long instanceId, int inkCost)` | 原子扣除墨水并把指定实例提升一级 |

普通业务失败由承担检查的 Store/System 记录包含实例 ID 或槽位的日志并返回 `false`；内部契约违约自然失败，不增加全量 `ValidateState`。

## 验收标准

- 一个 Store 同时原子维护法术和墨水；任何路径都不能产生重复位置、超容量、负墨水或重复 ID。
- 装备替换不暴露中间超容量状态；合成成功/失败和升级只标脏一次并在提交后发布事实。
- 存档 Data 不包含战斗状态、合成格显示索引或 Luban 静态事实。
- 不创建第二个法术资产 Store、测试或默认兜底实现。
