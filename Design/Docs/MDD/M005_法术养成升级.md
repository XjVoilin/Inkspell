# M005 法术养成升级

文档类型：MDD

- 来源模块设计：`../模块设计.md`
- 来源 GDD：`../GDD.md`

## 目标与边界

实现法术养成模块唯一 System，解释阶级与当前等级对应的成本、上限及主要数值成长，并请求法术资产原子扣墨水与升级。无 Store、Procedure、返还、重置或降级。

## 对应模块设计

- 所属模块：法术养成；落实“无 Store、一个 System、同步单 Store 提交”的角色规划。
- 墨水和等级继续由法术资产 Store 拥有；养成只拥有升级决策。

## 对应 GDD 内容

对应 §7.1、§10.4、§11、§14.3 第 4 条、§17.1、§18 升级边界、§19.1 第 12 项及 §20.7。

## 实施范围

### 创建

- `Tools/Luban/DataTables/Datas/法术升级_SpellUpgrade.xlsx`：`TbSpellUpgrade`，按法术种类、阶级与当前等级记录升级成本、下一等级和主要战斗数值倍率。
- `Assets/Game/Scripts/Runtime/Modules/SpellProgression/SpellUpgradeTypes.cs`：真实升级信息与成功/拒绝业务事实。
- `Assets/Game/Scripts/Runtime/Modules/SpellProgression/SpellProgressionSystem.cs`：唯一养成业务入口。

### 修改

- `Tools/Luban/DataTables/Datas/__tables__.xlsx`：登记升级表。

### 不涉及

- 不直接修改 Store，不执行战斗效果，不为已升级法术提供合成返还。
- 不创建 `ISpellProgressionSystem` 或只包装失败原因的 Result。

## 角色与职责

| 类型 | 所属模块 | JulyArch 角色 | 职责 | 必要协作 |
|---|---|---|---|---|
| `SpellProgressionSystem` | 法术养成 | System | 查询升级信息并判定、提交一次升级 | `SpellAssetSystem`、`IConfigSystem` |
| `SpellUpgradeInfo` | 法术养成 | 真实业务计算产物 | 表达成本、上限和升级前后主要倍率 | 详情 WindowData |
| `SpellUpgradeRejectedEvent` | 法术养成 | 业务事实 | 墨水不足或满级反馈 | 详情窗口 |
| `SpellUpgradedEvent` | 法术养成 | 业务事实 | 已提交的墨水、等级和倍率变化 | View、下一次战斗读取 |

## 状态与数据

无长期状态。`SpellUpgradeInfo` 包含实例 ID、当前/下一等级、成本、当前/下一主要数值倍率、是否满级和当前墨水；它是升级规则的真实计算产物。

## 行为与公开能力

| 类型 | 准确公开签名 | 语义 | 返回与失败处理 |
|---|---|---|---|
| `SpellProgressionSystem` | `public SpellUpgradeInfo GetUpgradeInfo(long instanceId)` | 计算详情展示与按钮状态 | 实例不存在属于调用契约错误；直接读取对应配置 |
| `SpellProgressionSystem` | `public bool TryUpgrade(long instanceId)` | 判定并提交单件升级 | 满级或墨水不足记录上下文、发布拒绝事实并返回 `false`；成功发布升级事实 |
| `SpellUpgradeInfo` | `public long InstanceId { get; }`、`public int CurrentLevel { get; }`、`public int NextLevel { get; }`、`public int InkCost { get; }`、`public float CurrentPowerMultiplier { get; }`、`public float NextPowerMultiplier { get; }`、`public bool IsMaxLevel { get; }`、`public int CurrentInk { get; }` | 详情与升级反馈的真实规则计算 | 不提供业务修改入口 |
| `SpellUpgradeRejectedEvent` | `public long InstanceId { get; }`、`public SpellUpgradeRejectReason Reason { get; }` | 详情窗口映射拒绝反馈 | 不携带本地化文本 |
| `SpellUpgradedEvent` | `public SpellUpgradeInfo Upgrade { get; }` | 已提交升级后的等级、成本与倍率变化 | View 刷新且战斗下次施法重新读取 |

`SpellUpgradeRejectReason` 只含 `InsufficientInk`、`MaxLevel`；实例不存在不伪装成普通业务状态。

## Luban 配置

升级表同时给养成查询与自动战斗读取；每条记录字段固定为 `spellType`、`tier`、`currentLevel`、`nextLevel`、`inkCost`、`currentPowerMultiplier`、`nextPowerMultiplier`、`isMaxLevel`。`__tables__.xlsx` 使用 `spellType+tier+currentLevel` 复合索引，生成 `TbSpellUpgrade.Get(SpellType spellType, int tier, int currentLevel)` 查询能力。

四种 `SpellType`、三个阶级分别建立以下五行，共 60 条记录。四种法术首版数值相同，但保留独立记录：

| `currentLevel` | `nextLevel` | `currentPowerMultiplier` | `nextPowerMultiplier` | 一阶 `inkCost` | 二阶 `inkCost` | 三阶 `inkCost` | `isMaxLevel` |
|---:|---:|---:|---:|---:|---:|---:|---:|
| 1 | 2 | 1.00 | 1.15 | 10 | 30 | 90 | false |
| 2 | 3 | 1.15 | 1.30 | 20 | 60 | 180 | false |
| 3 | 4 | 1.30 | 1.50 | 30 | 90 | 270 | false |
| 4 | 5 | 1.50 | 1.75 | 40 | 120 | 360 | false |
| 5 | 5 | 1.75 | 1.75 | 0 | 0 | 0 | true |

倍率乘于 `TbSpellCombat` 中该法术当前阶级的基础主要数值：火球、雷链与冰环对应伤害，护盾对应护盾值。冷却、范围、持续时间、连锁数和减速参数不乘该倍率。System 只依据 `isMaxLevel` 判定上限，不再用“缺少下一行”维护第二套规则；静态倍率不复制进 Store 或 C#。

## 验收标准

- 墨水不足和满级均不修改资产；成功只改变墨水和该实例等级。
- 升级事实足以显示墨水、等级和主要倍率变化，战斗不被追溯修改。
- 一个具体 System、无 Store/Procedure/Result/测试；作者源可生成且项目编译通过。
