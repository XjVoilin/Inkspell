# M007 自动战斗挑战运行

文档类型：MDD

- 来源模块设计：../模块设计.md
- 来源 GDD：../GDD.md

## 目标与边界

修改现有 AutoBattleSystem，使其只编排挑战生命周期，并把 M006 的 BattleRun 所有权和逐帧战斗规则交给内部普通类型 `BattleSimulation`。`RunChallengeAsync()` 的完成源仍表达等待、取消、异常和唯一胜负。删除仅充当完成容器的 BattleChallengeProcedure，避免 System 与具体 Procedure 双向依赖。模块不修改关卡进度、不自行开始下一关，也不生成场景或表现资源。

## 对应模块设计

- 所属模块：自动战斗；一个 System、无 Store、无模块内 Procedure。
- BattleSimulation 唯一拥有 BattleRun，并负责配置解释、敌人生成、施法、攻击、效果与胜负优先级；AutoBattleSystem 只负责初始化接线、异步生命周期、逐帧触发、事件与完成通知。BattleBook、EnemyRoster 和 SpellCooldownSet 封装局部不变量。
- 每次施法从 SpellAssetStore 读取当前装备实例；已发攻击使用冻结参数。

## 角色与职责

| 类型 | 所属模块 | JulyArch 角色 | 职责 | 必要协作 |
|---|---|---|---|---|
| AutoBattleSystem | 自动战斗 | System / IUpdatableSystem | 编排单次挑战的框架生命周期、事件和完成通知 | BattleSimulation、IConfigSystem |
| BattleSimulation | 自动战斗 | 普通类型 | 拥有并按战斗规则推进单次挑战运行态 | SpellAssetStore、战斗配置表 |
| BattleStateChangedEvent | 自动战斗 | 业务事实 | 通知显示重新查询 | 主窗口 |
| BattleChallengeEndedEvent | 自动战斗 | 业务事实 | 发布唯一 BattleOutcome | 关卡推进与 View |

## 状态与数据

System 字段持有 BattleSimulation、当前完成源和下一个 `BattleRunId`；BattleSimulation 持有当前 BattleRun。BattleRun 组合 BattleBook、EnemyRoster 和 SpellCooldownSet，它们分别保护生命/护盾、敌人集合/选敌以及槽位冷却的局部不变量。完成源非空同时表示单次战斗占用，只由最终化或异常完成；取消由 `RunChallengeAsync()` 的 `finally` 通知模拟停止运行态并释放占用。

## 行为与公开能力

| 类型 | 准确公开签名 | 语义 | 返回与失败处理 |
|---|---|---|---|
| AutoBattleSystem | public UniTask<BattleOutcome> RunChallengeAsync(int stageId, CancellationToken ct = default) | 从关卡起点运行一次挑战到胜负 | 并发挑战为内部违约；取消抛取消 |
| AutoBattleSystem | internal BattleRun CurrentRun { get; } | 向同程序集 WindowData 暴露当前战斗运行实例 | 调用方只读；未运行时读取最后一次或初始空实例 |
| AutoBattleSystem | public void OnUpdate(float deltaTime) | 前台逐帧触发 BattleSimulation 并转发可观察事件/结果 | 无挑战时不修改状态 |
| BattleSimulation | internal void Begin(long battleRunId, int stageId) | 建立新运行态并生成零时刻敌人 | stageId 必须存在 |
| BattleSimulation | internal BattleOutcome? Advance(float deltaTime) | 按固定顺序推进一帧并在终局时返回结果 | 仅在运行中调用 |
| BattleSimulation | internal void Stop() | 停止当前运行态 | 取消或异常清理时调用 |

## 关键行为

同一推进步按 GDD 顺序结算已发命中、死亡、胜利、敌人推进/攻击、失败与新施法。四槽冷却独立；无目标不消耗施法；护盾优先吸收且重复施放取较大值并刷新持续时间；胜负只最终化一次。

## 验收标准

- AutoBattleSystem 不再 GetStore<AutoBattleStore>()；状态由其 BattleSimulation 持有，随 System 生命周期存在且不持久化。
- 最后敌人死亡优先于其后续攻击；换装/升级只影响下一次施法。
- `RunChallengeAsync()` 真实等待并可取消，且 AutoBattleSystem 不依赖具体 Procedure。
- M999:I008 完成后不存在 BattleViewState、子 View 类型或 GetBattleViewState() 读取副本入口。
- 项目编译通过；不创建测试、Prefab、Scene 或美术资源。
