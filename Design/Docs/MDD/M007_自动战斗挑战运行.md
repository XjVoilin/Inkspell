# M007 自动战斗挑战运行

文档类型：MDD

- 来源模块设计：`../模块设计.md`
- 来源 GDD：`../GDD.md`

## 目标与边界

实现自动战斗模块唯一 System 与单次挑战 Procedure，在前台逐帧推进敌人、四槽施法、攻击与效果，并按固定优先级产生唯一胜负。只运行指定关卡的一次挑战，不修改关卡进度或自行开始下一关。

## 对应模块设计

- 所属模块：自动战斗；落实一个 System、每次挑战一个 Procedure。
- 每次合法施法重新读取法术资产；跨挑战循环仍归关卡推进。

## 对应 GDD 内容

对应 §6 全部、§7.2、§12.2、§13、§14.2—3、§18 战斗失败边界及 §20.7—9。

## 角色与职责

| 类型 | 所属模块 | JulyArch 角色 | 职责 | 必要协作 |
|---|---|---|---|---|
| `AutoBattleSystem` | 自动战斗 | System | 运行指定关卡、每帧推进并提供战场读取 | Store、资产 System、`IConfigSystem` |
| `BattleChallengeProcedure` | 自动战斗 | Procedure | 初始化一次挑战并等待其唯一结果 | AutoBattleSystem/Store |
| `BattleStateChangedEvent` | 自动战斗 | 业务事实 | 通知 WindowData 刷新战场事实 | 主界面 |
| `BattleChallengeEndedEvent` | 自动战斗 | 业务事实 | 发布唯一 `BattleOutcome` | 关卡推进与 View |

## 状态与数据

System 只保存当前 Procedure 等运行引用，不复制战场业务状态。Procedure 持有当次 `stageId` 与等待完成源；取消时终止当次挑战但不伪造胜负。

## 行为与公开能力

| 类型 | 准确公开签名 | 语义 | 返回与失败处理 |
|---|---|---|---|
| `AutoBattleSystem` | `public UniTask<BattleOutcome> RunChallengeAsync(int stageId, CancellationToken ct = default)` | 从关卡起点运行一次挑战直到胜负 | 同时已有挑战属于内部编排违约并自然失败；取消抛取消，不返回假结果 |
| `AutoBattleSystem` | `public BattleViewState GetBattleViewState()` | 获取当前挑战只读事实 | 未开始时返回明确的空闲业务状态 |
| `AutoBattleSystem` | `public void OnUpdate(float deltaTime)` | 前台逐帧推进当前挑战 | 无运行挑战时无状态修改 |
| `BattleStateChangedEvent` | `public readonly struct BattleStateChangedEvent` | 标记战场事实已完整提交 | WindowData 收到后重新查询，不携带 Store Data |
| `BattleChallengeEndedEvent` | `public BattleOutcome Outcome { get; }` | 发布当次唯一胜负 | 关卡推进和 View 只消费该结果 |

## 关键行为

- 出生、移动、接敌攻击、护盾先吸收、死亡、减速过期均由 Store 语义方法修改。
- 四槽冷却独立；无目标时不消耗施法，保持可再次判断的就绪状态。
- 火球单体；雷链从最近目标开始并选择附近未重复合法目标；冰环按范围伤害并减速；护盾取当前剩余值与新值较大者并刷新持续时间。
- 同一推进步先结算已产生命中，再移除死亡；无存活且无待出生敌人时胜利；否则生命归零时失败。最终状态提交后只发布一次结果。

## 验收标准

- 单次挑战可从配置编队推进到唯一胜负，最后敌人死亡优先于其后续攻击。
- 换装/升级只影响下一次施法，战斗与下方业务不互相暂停。
- System/Procedure 与当前 JulyArch API 一致：`IUpdatableSystem.OnUpdate(float)`、`ProcedureBase.OnExecuteAsync(CancellationToken)`、`RunProcedure()`。
- 不实现跨关循环、View、Prefab 或测试；项目编译通过。
