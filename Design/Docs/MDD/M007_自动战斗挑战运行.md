# M007 自动战斗挑战运行

文档类型：MDD

- 来源模块设计：../模块设计.md
- 来源 GDD：../GDD.md

## 目标与边界

修改现有 AutoBattleSystem，使其直接拥有 M006 的 AutoBattleState 并逐帧推进单次挑战；保留 BattleChallengeProcedure，因为它真实等待帧更新产生唯一胜负并支持取消。模块不修改关卡进度、不自行开始下一关，也不生成场景或表现资源。

## 对应模块设计

- 所属模块：自动战斗；一个 System、无 Store、每次挑战一个 Procedure。
- AutoBattleSystem 唯一拥有敌人、施法、攻击、效果与胜负优先级。
- 每次施法从 SpellAssetStore 读取当前装备实例；已发攻击使用冻结参数。

## 对应 GDD 内容

对应 §6、§7.2、§12.2、§13、§14.2—3、§18 与 §20.7—9。

## 角色与职责

| 类型 | 所属模块 | JulyArch 角色 | 职责 | 必要协作 |
|---|---|---|---|---|
| AutoBattleSystem | 自动战斗 | System / IUpdatableSystem | 拥有并推进单次挑战能力运行态 | SpellAssetStore、IConfigSystem |
| BattleChallengeProcedure | 自动战斗 | Procedure | 启动一次挑战并等待唯一胜负或取消 | AutoBattleSystem |
| BattleStateChangedEvent | 自动战斗 | 业务事实 | 通知显示重新查询 | 主窗口 |
| BattleChallengeEndedEvent | 自动战斗 | 业务事实 | 发布唯一 BattleOutcome | 关卡推进与 View |

## 状态与数据

System 字段持有当前 AutoBattleState 和当前 Procedure 引用。Procedure 只持有 stageId、完成源和本次结果。WindowData 通过 System.CurrentState 按只读约定直接读取实时状态，再转换为可由 GM 覆盖的显示数据；不建立领域读取副本。

## 行为与公开能力

| 类型 | 准确公开签名 | 语义 | 返回与失败处理 |
|---|---|---|---|
| AutoBattleSystem | public UniTask<BattleOutcome> RunChallengeAsync(int stageId, CancellationToken ct = default) | 从关卡起点运行一次挑战到胜负 | 并发挑战为内部违约；取消抛取消 |
| AutoBattleSystem | internal AutoBattleState CurrentState { get; } | 向同程序集 WindowData 暴露当前挑战实时状态 | 调用方只读；未运行时读取当前空闲状态 |
| AutoBattleSystem | public void OnUpdate(float deltaTime) | 前台逐帧推进当前挑战 | 无挑战时不修改状态 |
| BattleChallengeProcedure | protected override UniTask OnExecuteAsync(CancellationToken ct) | 调用 System 开始并等待结果 | 取消不返回假胜负 |

## 关键行为

同一推进步按 GDD 顺序结算已发命中、死亡、胜利、敌人推进/攻击、失败与新施法。四槽冷却独立；无目标不消耗施法；护盾优先吸收且重复施放取较大值并刷新持续时间；胜负只最终化一次。

## 验收标准

- AutoBattleSystem 不再 GetStore<AutoBattleStore>()，状态随 System 生命周期存在且不持久化。
- 最后敌人死亡优先于其后续攻击；换装/升级只影响下一次施法。
- Procedure 仍真实等待并可取消，Window/GameView 不构造或运行它。
- M999:I008 完成后不存在 BattleViewState、子 View 类型或 GetBattleViewState() 读取副本入口。
- 项目编译通过；不创建测试、Prefab、Scene 或美术资源。
