# M008 关卡连续推进

文档类型：MDD

- 来源模块设计：`../模块设计.md`
- 来源 GDD：`../GDD.md`

## 目标与边界

实现关卡推进模块唯一持久 Store、System 与单次关卡循环 Procedure。维护当前最高关，调用自动战斗取得唯一结果，胜利时只推进一关，失败或最大关胜利后停顿并继续当前关。

## 对应模块设计

- 所属模块：关卡推进；一个 Store、一个 System，每次“挑战—提交—停顿”一个 Procedure。
- 关卡推进是跨挑战循环唯一编排者；自动战斗不反向修改关卡状态。

## 对应 GDD 内容

对应 §4.1—3、§6.3、§8.4、§13.1、§14、§17.4、§18 最大关/失败恢复及 §20.8—9、12。

## 实施范围

### 创建

- `Tools/Luban/DataTables/Datas/关卡推进_StageProgression.xlsx`：`TbStageProgression`，按顺序关卡记录 `stageId`、`isMaxStage`、`victoryPauseSeconds` 与 `failurePauseSeconds`。
- `Assets/Game/Scripts/Runtime/Modules/StageProgression/StageProgressionStoreData.cs`：初始化标记与当前最高关。
- `Assets/Game/Scripts/Runtime/Modules/StageProgression/StageProgressionStore.cs`：单向提交关卡增长。
- `Assets/Game/Scripts/Runtime/Modules/StageProgression/StageProgressionSystem.cs`：查询并控制连续挑战生命周期。
- `Assets/Game/Scripts/Runtime/Modules/StageProgression/StageChallengeProcedure.cs`：运行一次挑战、提交结果和停顿。
- `Assets/Game/Scripts/Runtime/Modules/StageProgression/StageProgressionEvents.cs`：进度增长事实。

### 修改

- `Tools/Luban/DataTables/Datas/__tables__.xlsx`：登记关卡推进表。

### 不涉及

- 不保存敌人或关内进度，不解释生成间隔，不提供选关/跳关/手动开始。

## 角色与职责

| 类型 | 所属模块 | JulyArch 角色 | 职责 | 必要协作 |
|---|---|---|---|---|
| `StageProgressionStore` | 关卡推进 | Store | 持久当前最高关并只允许单步增长 | `TbStageProgression` |
| `StageProgressionSystem` | 关卡推进 | System | 查询进度并连续创建挑战 Procedure | AutoBattleSystem |
| `StageChallengeProcedure` | 关卡推进 | Procedure | 一次挑战、唯一提交及配置停顿 | Store、AutoBattleSystem |
| `StageProgressChangedEvent` | 关卡推进 | 业务事实 | 仅在关卡确实增长时发布 | 法术生成与 View |

## 状态与数据

`StageProgressionStoreData` 只含 `bool Initialized` 与 `int CurrentHighestStageId`。新进度读取表中首关；最大关由表标识，不在 C# 固定为 10。System 的循环取消源属于运行控制，不是业务进度。

## 行为与公开能力

| 类型 | 准确公开签名 | 语义 | 返回与失败处理 |
|---|---|---|---|
| `StageProgressionSystem` | `public int CurrentStageId { get; }` | 当前正在自动挑战的最高关 | 只读 |
| `StageProgressionSystem` | `public void StartContinuousChallenges()` | 启动唯一连续挑战循环 | 已运行时保持幂等，不创建第二循环 |
| `StageProgressionSystem` | `public void StopContinuousChallenges()` | 停止后续挑战并取消当前等待 | 不修改当前最高关 |
| `StageProgressChangedEvent` | `public int CurrentStageId { get; }` | 关卡确实增长后的新最高关 | 法术生成更新间隔，View 刷新关卡文本 |

System 每轮创建新的 `StageChallengeProcedure` 并通过 JulyArch `RunProcedure()` 运行。Procedure 胜利且非最大关时请求 Store 增长一关；失败或最大关胜利保持原关，按各自停顿后结束，System 再创建下一轮。

## Luban 配置

`TbStageProgression` 作者源字段固定为 `stageId:int`、`isMaxStage:bool`、`victoryPauseSeconds:float`、`failurePauseSeconds:float`。按顺序写入第 1—10 关，只有第 10 关 `isMaxStage=true`；每关 `victoryPauseSeconds=1.0`、`failurePauseSeconds=2.0`。只验证当前 GDD 要求的顺序数据能生成，不在运行时预巡检记录数或连续性。

## 验收标准

- 新存档从配置首关开始；只能胜利后单步增长，最大关不增长。
- 每次挑战只消费一个 `BattleOutcome`，失败/重试清理仍由自动战斗新挑战完成。
- Store 可持久化且不含关内状态；无第二个 System/Store、选关入口或测试。
- Luban 生成与项目编译通过。
