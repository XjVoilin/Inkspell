# M008 关卡连续推进

文档类型：MDD

- 来源模块设计：../模块设计.md
- 来源 GDD：../GDD.md

## 目标与边界

确认并保持现有关卡推进 Store、System 与 StageChallengeProcedure 的角色边界：Store 持久当前最高关；System 维持连续挑战生命周期；Procedure 真实等待自动战斗结果、提交胜利进度并等待配置停顿。模块不模拟战斗、不解释生成间隔、不提供选关。

## 对应模块设计

- 所属模块：关卡推进；一个持久 Store、一个 System、每次挑战一个 Procedure。
- 关卡推进是跨挑战循环唯一编排者；自动战斗只返回当次唯一结果。
- StageChallengeProcedure 满足等待、嵌套和取消成立条件，继续保留。

## 对应 GDD 内容

对应 §4.1—3、§6.3、§8.4、§13.1、§14、§17.4、§18 与 §20.8—9、12。

## 角色与职责

| 类型 | 所属模块 | JulyArch 角色 | 职责 | 必要协作 |
|---|---|---|---|---|
| StageProgressionStore | 关卡推进 | Store | 持久当前最高关并只允许胜利单步增长 | TbStageProgression |
| StageProgressionSystem | 关卡推进 | System | 控制连续挑战/取消生命周期 | StageProgressionStore、AutoBattleSystem |
| StageChallengeProcedure | 关卡推进 | Procedure | 等待一次挑战、提交进度并等待胜负停顿 | Store、AutoBattleSystem |
| StageProgressChangedEvent | 关卡推进 | 业务事实 | 只在进度真实增长时发布 | 生成与 View |

## 状态与数据

Store Data 继续只含 Initialized 与 CurrentHighestStageId。System 的 CancellationTokenSource 是长期循环控制，不是持久进度。Procedure 只持有本轮 StageProgression 配置和调用时 CancellationToken。

## 行为与公开能力

| 类型 | 准确公开签名 | 语义 | 返回与失败处理 |
|---|---|---|---|
| StageProgressionStore | internal int CurrentStageId { get; } | 当前最高且下一次挑战的关卡 | 只读 |
| StageProgressionSystem | public void StartContinuousChallenges() | 启动唯一连续循环 | 已运行时幂等，不创建第二循环 |
| StageProgressionSystem | public void StopContinuousChallenges() | 取消当前等待和后续循环 | 不修改关卡 Store |
| StageProgressChangedEvent | public int CurrentStageId { get; } | 真实增长后的新关卡 | 生成更新间隔，View 刷新 |

## Luban 配置

复用现有关卡推进作者源及当前 10 关、最大关和胜负停顿配置；不在 C# 复制数值或运行时巡检表连续性。

## 验收标准

- Store 只持久当前最高关，胜利最多增长一关且最大关不增长。
- Procedure 先等待战斗，再提交进度，再等待配置停顿；失败和最大关胜利保持当前关。
- System 可取消并串行创建下一轮，不形成第二挑战循环。
- 编译通过；不创建测试、Scene、Prefab 或美术资源。
