# M012 战场显示

文档类型：MDD

- 来源模块设计：../模块设计.md
- 来源 GDD：../GDD.md

## 目标与边界

确认并复用现有战场 WindowData/GameView，使其渲染主 WindowData 已经转换完成的战场显示数据。自动战斗状态不再归 AutoBattleStore；GameView 不读取 AutoBattleSystem、不生成敌人业务对象、不推进战斗或决定胜负。

## 对应模块设计

- 所属范围：自动战斗的 UI 表现集成，不新增业务模块。
- 权威运行态随 AutoBattleSystem 生命周期存在。
- M010 直接从实时运行态转换 BattlefieldViewData，GameView 只渲染和播放已提交事实；战场显示数据链不经过 BattleViewState，迁移兼容类型仍由 M999:I008 统一删除。

## 对应 GDD 内容

对应 §6、§7.2、§13.2、§15.1、§15.3、§16 与 §20.7—9、13—14。

## 实施范围

### 创建

无。

### 修改

无。M010 只改变 BattlefieldViewData 的数据来源，不改变现有显示 Data 与 GameView 契约。

### 复用

- Assets/Game/Scripts/Runtime/Views/UIBattlefieldGameView.cs、UIEnemyBattleGameView.cs：现有纯 Data 渲染。
- Assets/Game/Scripts/Runtime/Views/BattlefieldViewData.cs：现有 GM 可写显示输入。
- Assets/Game/Scripts/Runtime/Views/UIInkspellMainWindow.cs：现有战斗事件刷新与结果播放。
- 现有 UIProgressBar、敌人显示项映射、攻击/效果 ID 去重与胜负表现入口。
- 现有 Language.xlsx 战斗文本键。

### 不涉及

- 不创建 Sprite、Spine、动画、弹道、特效、Prefab、Scene 或材质。
- 不让动画完成决定伤害、效果或胜负是否成立。

## 前置依赖

无。现有 BattlefieldViewData、GameView 和战斗事件已经存在；目标调整不要求先实施其他 MDD。

## 延迟集成

无。M012 自身的战场显示职责已经能够独立完成；视觉资源与 Inspector 绑定不属于 M999。M007/M010 迁移后遗留的 `BattleViewState` 兼容类型与 `GetBattleViewState()` 入口仍按既有 M999:I008 删除，不属于本 MDD 的显示实现或延迟连接。

## 角色与职责

| 类型 | 所属范围 | JulyArch 角色 | 职责 | 必要协作 |
|---|---|---|---|---|
| UIBattlefieldGameView | UI 表现集成 | GameView | 渲染战场并播放已提交事实 | BattlefieldViewData |
| UIEnemyBattleGameView | UI 表现集成 | GameView | 渲染单敌人生命、位置与减速 | EnemyBattleViewData |
| BattlefieldViewData | UI 表现集成 | ViewData | 战场区域唯一显示输入 | UIInkspellMainWindowData |

## 状态与数据

GameView 只保存显示项映射、已播放 ID 和动画进度等纯表现状态。BattlefieldViewData 包含战斗运行标识、魔法书、敌人、施法时冻结的冷却总时长、攻击目标/飞行时间与效果范围/持续时间等显示值，不引用可写 BattleRun。

## 行为与公开能力

| 类型 | 准确公开签名 | 语义 | 返回与失败处理 |
|---|---|---|---|
| UIBattlefieldGameView | public void Render(BattlefieldViewData data) | 更新生命、护盾、敌人、冷却和效果 | 不访问 Store/System |
| UIBattlefieldGameView | public void PlayChallengeResult(bool victory) | 播放已提交胜负 | 不反向修改结果 |
| UIEnemyBattleGameView | public void Render(EnemyBattleViewData data) | 更新单敌人显示 | 重复项不实现 ISingletonView |

## View 代码

生命、护盾与冷却继续使用 UIProgressBar.SetValue(float, float)，核心状态同时有文本/数值。路径归一化只影响显示映射，不写回战斗状态。

## 验收标准

- 战场显示数据链不把 AutoBattleStore 写成状态所有者，`UIInkspellMainWindowData` 直接从 `AutoBattleSystem.CurrentRun` 转换 `BattlefieldViewData`，Window/GameView 不消费额外读取模型。
- Window/GameView 只从 Data 渲染，无目标选择、伤害或胜负逻辑。
- 受击、减速、死亡、护盾、胜利、失败与重试仍有可区分表现入口。
- 编译通过；不创建测试、Prefab、Scene 或美术资源。
