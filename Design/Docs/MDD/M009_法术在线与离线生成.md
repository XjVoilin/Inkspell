# M009 法术在线与离线生成

文档类型：MDD

- 来源模块设计：`../模块设计.md`
- 来源 GDD：`../GDD.md`

## 目标与边界

实现法术生成模块唯一持久 Store、System 与离线结算 Procedure。在线按实际时间产生一阶法术，合成区满时保留具体待领取产物；空位出现后自动移交。离线只计算生成，不模拟战斗。

## 对应模块设计

- 所属模块：法术生成；一个 Store、一个 System，离线结算及紧随补入使用一次 Procedure。
- 法术生成是待领取到资产的唯一编排者；关卡只发布进度事实，不写生成状态。

## 对应 GDD 内容

对应 §4、§8、§14.1—2、§17.3、§18 生成边界、§19.1 第 13—15 项及 §20.10—12。

## 角色与职责

| 类型 | 所属模块 | JulyArch 角色 | 职责 | 必要协作 |
|---|---|---|---|---|
| `SpellGenerationStore` | 法术生成 | Store | 持久待领取、周期、间隔和离线锚点 | SaveSystem |
| `SpellGenerationSystem` | 法术生成 | System | 在线推进、前后台记录、间隔更新与自动补入 | 资产、关卡、`ITimeSystem`、配置 |
| `OfflineGenerationProcedure` | 法术生成 | Procedure | 一次有上限离线结算、自动补入并产生已提交结果 | Store、资产 System |
| `OfflineGenerationOutcome` | 法术生成 | 真实业务结果 | 表达合法时长、产生数和自动补入数 | M014 |

## 状态与数据

- Store Data：`bool Initialized`、`List<SpellType> PendingSpells`、`float CycleProgressSeconds`、`float ActiveIntervalSeconds`、`long InactiveSinceUtcSeconds`、`bool HasInactiveAnchor`。
- 待领取保存具体法术类型，保证重启不会重新抽取或改变结果。
- 设备时间仅在外部时间边界校验一次：负时长夹为 0，正时长上限取 Luban 离线上限；间隔取离线锚点时已持久生效值并不低于配置最小值。

## 行为与公开能力

| 类型 | 准确公开签名 | 语义 | 返回与失败处理 |
|---|---|---|---|
| `SpellGenerationSystem` | `public int PendingCount { get; }` | 待领取数量 | 只读 |
| `SpellGenerationSystem` | `public float CurrentCycleProgressSeconds { get; }` | 当前周期进度 | 只读 |
| `SpellGenerationSystem` | `public float CurrentIntervalSeconds { get; }` | 当前有效间隔 | 只读 |
| `SpellGenerationSystem` | `public UniTask<OfflineGenerationOutcome> SettleOfflineAsync(CancellationToken ct = default)` | 结算一次持久锚点，提交待领取并执行可完成的自动补入 | 无锚点返回产生数为 0 的真实结算；取消不伪造结果；返回时业务结果已成立 |
| `SpellGenerationSystem` | `public void OnUpdate(float deltaTime)` | 在线产生、累积并尝试补入 | 满格仅停止补入 |
| `OfflineGenerationOutcome` | `public OfflineGenerationOutcome(long elapsedSeconds, int generatedCount, int transferredCount)` | 构造一次已完成离线结算 | 参数均为生成模块提交后的合法结果 |
| `OfflineGenerationOutcome` | `public long ElapsedSeconds { get; }`、`public int GeneratedCount { get; }`、`public int TransferredCount { get; }` | 供启动连接与收益 WindowData 使用 | 不提供状态修改入口 |

自动补入逐个调用资产接收；只有返回 `true` 后才从队首移除。资产发布容量增加事实时再次补入；关卡增长事实只更新间隔，不重算已过去周期。

## Luban 配置

`TbSpellGeneration` 为单条配置，字段固定为 `long offlineLimitSeconds`、`float minimumIntervalSeconds`、`list<SpellType> spellTypes` 与 `list<int> weights`。首版值为离线上限 `28800` 秒、最小间隔 `45` 秒，生成池依次为火球、雷链、冰环、护盾，权重均为 `1`。

`TbStageGeneration` 字段固定为 `int stageId` 与 `float intervalSeconds`；第 1—10 关间隔依次为 `180、165、150、135、120、105、90、75、60、45` 秒。最小间隔和离线上限只有一份来源，不在 C# 镜像。

## 验收标准

- 在线周期无论合成区是否满都产生并持久待领取；移交严格“资产先确认、队列后移除”。
- 离线时长不为负、不超过上限，使用离线期间有效间隔；先增加待领取，再执行可完成的自动补入，二者结束后才返回包含补入数量的真实结果。
- System 正确使用当前 `ITimeSystem.ServerTimeSeconds` 与 `IUpdatableSystem.OnUpdate(float)` API。
- 不模拟战斗、创建 View/测试/场景对象；Luban 生成和编译通过。
