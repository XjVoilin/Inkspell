# M003 法术资产业务入口

文档类型：MDD

- 来源模块设计：../模块设计.md
- 来源 GDD：../GDD.md

## 目标与边界

收窄现有 SpellAssetSystem，只保留持久化恢复后的新档初始化、容量集中解释和依赖配置的未装备法术稳定排列。锁定、装备、实例/墨水查询及合成、升级、生成提交全部由 SpellAssetStore 直接提供，System 不再充当统一门面。

## 对应模块设计

- 所属模块：法术资产；落实一个具有初始化生命周期和配置派生解释的 System。
- System 成立依据是恢复顺序、新档补充、容量解释和稳定排序的集中责任。
- Store 内部不变量与同步原子动作仍唯一属于 M002。

## 对应 GDD 内容

对应 §4.1、§5、§9.1、§14.1、§17.1、§17.5 与 §20.2；具体配置事实不复制进 C#。

## 实施范围

### 创建

无。

### 修改

- Assets/Game/Scripts/Runtime/Modules/SpellAssets/SpellAssetSystem.cs：新增 GetSortedCraftingAreaSpells()，基于 Store.GetCraftingAreaSpellStates() 返回 SpellInstanceState 实时引用的只读排序列表；保留初始化与 CraftingCapacity。
- 为保证后续消费者 M004—M013 可按顺序迁移，现有 MagicInk、RemainingCraftingCapacity、实例查询、语义转发和旧 Snapshot 查询在本 MDD 中仅作为编译迁移入口保留；全部调用方迁移后由 M999:I008 一次删除。

### 复用

- 现有 OnInitializeAsync() 读取 TbSpellAssetRule/TbSpellDefinition 并调用 SpellAssetStore.Initialize() 的恢复后初始化顺序。
- 现有“显示优先级后按 InstanceId”排序规则。

### 不涉及

- 不解释合成、升级、生成或战斗规则。
- 不增加项目级接口、Result、配置聚合器、静态入口或生命周期守卫。

## 前置依赖

- M002：需要目标 SpellAssetStore 的实时只读实例查询与初始化入口。

## 延迟集成

- M999:I008：全部调用方迁移后删除旧 GetCraftingAreaSpells()/Snapshot 与所有 Store 转发入口，使最终 System 只保留下表能力。

## 角色与职责

| 类型 | 所属模块 | JulyArch 角色 | 职责 | 必要协作 |
|---|---|---|---|---|
| SpellAssetSystem | 法术资产 | System | 恢复后初始化、容量解释、配置派生稳定排列 | SpellAssetStore、IConfigSystem |

## 状态与数据

System 不拥有独立业务状态。它缓存现有配置表引用和 Store 引用；排序结果是新的只读列表，但列表项仍是 Store 的实时 SpellInstanceState，调用方只读且不持久保存为第二真相。

## 行为与公开能力

| 类型 | 准确签名 | 语义 | 返回与失败处理 |
|---|---|---|---|
| SpellAssetSystem | public int CraftingCapacity { get; } | 配置行列解释出的合成区容量 | 只读 |
| SpellAssetSystem | internal IReadOnlyList<SpellInstanceState> GetSortedCraftingAreaSpells() | 按配置优先级、再按实例 ID 排列未装备实例 | 返回新只读列表；不修改 Store |
| SpellAssetSystem | protected override UniTask OnInitializeAsync() | 在 Store 恢复后建立容量边界和必要新档初始资产 | Framework 生命周期保证只调用一次 |

## 验收标准

- 删除 System 后仍不能简单由调用方替代其恢复顺序和配置排序知识，角色成立。
- M999:I008 完成后，System 不再转发 Store 的实例查询、墨水、锁定、装备、生成、合成或升级提交。
- 未装备排列仍稳定，且不创建 SpellSnapshot、IXXSystem、Result 或配置巡检。
- M999:I008 完成后不存在旧快照入口。
