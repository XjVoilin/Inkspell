# M010 主界面窗口与显示数据

文档类型：MDD

- 来源模块设计：`../模块设计.md`
- 来源 GDD：`../GDD.md`

## 目标与边界

建立竖屏唯一主界面 Window、WindowData、窗口 ID 和常驻状态刷新骨架。Window 同时协调战场、装备与合成子区域，但不拥有业务状态、不直接修改 Store、不运行 Procedure。本 MDD 不交付子区域具体拖拽或战场渲染。

## 对应模块设计

- 所属范围：跨模块 View，不新增业务模块，也不改变六个业务模块职责。
- 落实全局依赖中“主界面 → 业务 System”和“WindowData 是唯一显示输入”。

## 对应 GDD 内容

对应 §3、§4、§15、§19.1 第 1 项、§20.1 和 §20.13—14。界面比例属于 Prefab 布局，本 MDD 仅提供 C# 显示契约。

## 实施范围

### 创建

- `Assets/Game/Scripts/Runtime/Views/UIWindowID.cs`：统一纯常量容器，保留现有 `UIAwardDisplayWindow = 11` 并新增 `UIInkspellMainWindow = 12`。
- `Assets/Game/Scripts/Runtime/Views/UIInkspellMainWindow.cs`：继承 `UIView`，管理页面生命周期、业务事件订阅和子区域协调。
- `Assets/Game/Scripts/Runtime/Views/UIInkspellMainWindowData.cs`：默认从各具体业务 System 组装首屏与常驻状态。
- `Assets/Game/Scripts/Runtime/Views/MainStatusViewData.cs`：关卡、墨水、待领取、生成周期和魔法书概要显示数据。

### 修改

- `Tools/Luban/DataTables/Datas/UIWindow.xlsx`：新增 ID 12、`windowName=UIInkspellMainWindow` 的主界面记录，层级与遮罩按常驻主页面设置。
- `Tools/Luban/DataTables/Datas/Language.xlsx`：新增主界面常驻标签与格式化文本键。

### 不涉及

- 不创建或修改 Prefab、Scene、Canvas、安全区、图片或 Inspector 绑定。
- 不在 WindowData 执行业务动作、导航或 Procedure。

## 前置依赖

- M003、M005、M007、M008、M009：默认 WindowData 需要这些具体 System 的只读能力组装首屏；没有假接口或占位数据源。

## 延迟集成

- M999:I006：主场景切换后通过 `IUISystem.OpenAsync(UIWindowID.UIInkspellMainWindow, data)` 打开主界面。
- M999:I007：组合根先取得已完整提交并自动补入的离线结算结果，再打开主窗口和按需展示收益，最后启动连续挑战；Window 不编排。

## 角色与职责

| 类型 | 所属模块 | JulyArch 角色 | 职责 | 必要协作 |
|---|---|---|---|---|
| `UIInkspellMainWindow` | 跨模块 View | Window | 页面级生命周期、事件刷新与玩家意图转交 | 具体业务 System、子 GameView |
| `UIInkspellMainWindowData` | 跨模块 View | WindowData | 查询并组装唯一显示输入 | `ArchContext.Current` 查询能力 |
| `MainStatusViewData` | 跨模块 View | ViewData | 常驻数字与进度显示 | WindowData |
| `UIWindowID` | UI 机制 | 纯常量 | 与 `TbUIWindow` 一一对应 | Luban UIWindow 表 |

## 状态与数据

Window 只保存注入的 `UIInkspellMainWindowData` 与页面级纯表现状态。WindowData 不缓存可写 Store Data；刷新时重新读取关卡、墨水、待领取、生成进度/间隔和战场生命概要。

## 行为与公开能力

| 类型 | 准确公开签名 | 语义 | 返回与失败处理 |
|---|---|---|---|
| `UIWindowID` | `public const int UIInkspellMainWindow = 12` | 主窗口配置 ID | 必须与 `TbUIWindow` 一致 |
| `UIInkspellMainWindowData` | `public UIInkspellMainWindowData()` | 正常首屏查询构造；也作为未注入默认 Data | Framework/业务契约缺失自然失败，不生成假数据 |
| `UIInkspellMainWindowData` | `public MainStatusViewData Status { get; private set; }` | 主状态唯一显示输入 | 由刷新更新 |
| `UIInkspellMainWindowData` | `public void RefreshStatus()` | 重新组装常驻状态 | 不修改任何 Store |
| `UIInkspellMainWindowData` | `public void RefreshAll()` | 调用当前已实现的各局部刷新 | 后续 MDD 可按同一显示职责增量扩展 |

## View 代码

- Window 类型严格为 `UIInkspellMainWindow`，ID 常量同名，Luban `windowName` 同名。
- `OnBeforeOpen()` 使用 `GetData<UIInkspellMainWindowData>() ?? new UIInkspellMainWindowData()`，随后仅渲染 Data。
- `OnOpen()` 订阅最小业务事实，回调先调用 Data 刷新，再渲染；`UIView` 生命周期自动清理订阅。
- 常驻生成进度使用已安装 `UIProgressBar.SetValue(float current, float maximum)`；普通点击使用 `UISmartButton`。

## Luban 配置

UIWindow 沿用已有文件名和表结构，不因新增记录重命名。Language 使用如 `MAIN_STAGE`、`MAIN_MAGIC_INK`、`MAIN_PENDING` 的稳定键，文本不固化到图片。

## 验收标准

- Window、ID 常量和 `TbUIWindow` 三者名称/数值一致；每个 Window 有 WindowData 且未注入时创建默认 Data。
- 正常运行和 GM 显示只根据 Data 渲染；Window 不读 Store、不写业务状态。
- C# 与 Luban 生成编译通过；Prefab/Scene/Inspector 缺口明确不在本 MDD 交付内。
- 不创建测试或美术资源。
