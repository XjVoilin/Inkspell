# M006 自动战斗配置与状态

文档类型：MDD

- 来源模块设计：`../模块设计.md`
- 来源 GDD：`../GDD.md`

## 目标与边界

建立自动战斗所需的 Luban 战斗事实、一次挑战的非持久权威 Store 和对外只读战场数据。负责战斗状态表示与原子演进语义，不负责跨挑战循环、关卡进度或 View 表现。

## 对应模块设计

- 所属模块：自动战斗；落实唯一非持久 Store 规划。
- Store 拥有魔法书、敌人、施法冷却、已发攻击、效果与唯一结果；新挑战完整清除旧状态。

## 对应 GDD 内容

对应 §6、§7.2、§12.2、§13、§14.2—3、§17.4、§18 战斗边界和 §19.1 第 2—6 项。

## 实施范围

### 创建

- `Tools/Luban/DataTables/Datas/战斗规则_BattleRule.xlsx`：单条 `TbBattleRule`，字段为 `int id`、`float bookMaxHealth`、`float enemySpawnPosition`、`float bookContactPosition`、`float attackTravelSeconds`。
- `Tools/Luban/DataTables/Datas/法术战斗_SpellCombat.xlsx`：`TbSpellCombat`，以 `spellType+tier` 为复合索引，字段为 `SpellType spellType`、`int tier`、`float baseDamage`、`float baseShield`、`float cooldownSeconds`、`float effectRange`、`float effectDurationSeconds`、`int chainTargetCount`、`float slowMultiplier`。
- `Tools/Luban/DataTables/Datas/敌人_Enemy.xlsx`：`TbEnemy`，以 `EnemyType enemyType` 为键，字段为 `float maxHealth`、`float moveSpeedPerSecond`、`float attackDamage`、`float attackIntervalSeconds`。
- `Tools/Luban/DataTables/Datas/关卡战斗_StageBattle.xlsx`：`TbStageBattle`，以 `int stageId` 为键，并通过 `list<StageEnemySpawn> spawns` 记录关卡编队及出生时机。
- `Assets/Game/Scripts/Runtime/Modules/AutoBattle/AutoBattleStoreData.cs`：挑战、魔法书、敌人、攻击、效果与槽位冷却 Data。
- `Assets/Game/Scripts/Runtime/Modules/AutoBattle/AutoBattleStore.cs`：继承 `StoreBase<AutoBattleStoreData>`。
- `Assets/Game/Scripts/Runtime/Modules/AutoBattle/BattleDomainTypes.cs`：`BattleOutcome`、`BattleViewState` 及敌人、冷却、已发攻击与效果的只读子数据。

### 修改

- `Tools/Luban/DataTables/Datas/__enums__.xlsx`：新增 `EnemyType`；法术行为直接由 `SpellType` 决定，不另建重复行为枚举。
- `Tools/Luban/DataTables/Datas/__beans__.xlsx`：新增 `StageEnemySpawn` Bean，字段为 `EnemyType enemyType` 与 `float spawnTimeSeconds`。
- `Tools/Luban/DataTables/Datas/__tables__.xlsx`：登记四张表。

### 不涉及

- 不持久化任何战斗 Data，不创建第二个 Store 或战斗 System。
- 不在 C# 重复敌人数值、四种法术参数或关卡编队。

## 角色与职责

| 类型 | 所属模块 | JulyArch 角色 | 职责 | 必要协作 |
|---|---|---|---|---|
| `AutoBattleStoreData` | 自动战斗 | Store Data | 一次挑战全部权威运行时状态 | 不参与持久化 |
| `AutoBattleStore` | 自动战斗 | Store | 开始挑战、推进敌人/攻击/效果并最终化结果 | M007 System |

## 状态与数据

- `AutoBattleStoreData` 包含挑战 ID、关卡 ID、是否运行、魔法书当前/最大生命与护盾、出生进度、敌人集合、槽位冷却、已发攻击/效果及可空最终结果。
- 敌人状态包含唯一运行时 ID、配置种类、生命、路径位置、攻击计时和减速剩余时长/倍率。
- 攻击在发起时冻结本次命中所需数值；后续装备或升级不改写它。该冻结数据是 GDD 明确的跨帧提交一致性边界，不是通用 Snapshot。
- `BattleViewState` 由 Store Data 转换为不可写集合，只供读取与 WindowData 组装；敌人、冷却、已发攻击和效果都转换为只读业务值，不暴露 Store Data 对象。

## Luban 配置

关卡编队通过 Bean 列表表达敌人类型和出生时间；首版单路径不引入路线表。`TbSpellCombat` 保存阶级基础值，M005 的等级倍率在实际施法时读取并组合，避免在两表重复等级完整数值。

`TbBattleRule` 唯一记录为：`id=1`、`bookMaxHealth=100`、`enemySpawnPosition=1.0`、`bookContactPosition=0.0`、`attackTravelSeconds=0.2`。路径位置采用从出生点 `1.0` 到魔法书接触点 `0.0` 的归一化业务坐标。

`TbSpellCombat` 首版验证基线如下；伤害法术的 `baseShield=0`，护盾的 `baseDamage=0`，不适用的范围、持续、连锁与减速字段分别使用 `0`、`0`、`0` 与 `1.0`：

| `spellType` | `tier` | `baseDamage` | `baseShield` | `cooldownSeconds` | `effectRange` | `effectDurationSeconds` | `chainTargetCount` | `slowMultiplier` |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| Fireball | 1 / 2 / 3 | 12 / 24 / 48 | 0 | 1.5 | 0 | 0 | 0 | 1.0 |
| ChainLightning | 1 / 2 / 3 | 9 / 18 / 36 | 0 | 2.0 | 0.25 | 0 | 2 / 3 / 4 | 1.0 |
| FrostRing | 1 / 2 / 3 | 7 / 14 / 28 | 0 | 2.5 | 0.18 / 0.22 / 0.26 | 2.0 / 2.5 / 3.0 | 0 | 0.60 / 0.55 / 0.50 |
| Shield | 1 / 2 / 3 | 0 | 20 / 40 / 80 | 4.0 | 0 | 3.0 | 0 | 1.0 |

## 验收标准

- 新挑战能彻底替换旧战斗 Data；Store 不标为持久化。
- 配置覆盖四种法术、四类敌人与十关编队，但 C# 无逐项内容常量。
- 已发攻击参数不会被换装/升级追溯改变。
- 一个 Store、无 System/View/测试；Luban 生成与编译通过。
