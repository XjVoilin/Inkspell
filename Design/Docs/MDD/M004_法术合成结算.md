# M004 法术合成结算

文档类型：MDD

- 来源模块设计：`../模块设计.md`
- 来源 GDD：`../GDD.md`

## 目标与边界

实现法术合成模块唯一 System 与一次性 Procedure：验证两个实例，按配置独立随机结算，并请求法术资产原子提交成功产物或失败墨水。无历史、保底、预览、撤销或 View 表现。

## 对应模块设计

- 所属模块：法术合成；无 Store，一个 System，每次合法二合一个 Procedure。
- 法术合成是二合事务唯一编排者；法术资产只执行最终单 Store 提交。

## 对应 GDD 内容

对应 §10、§11.1、§14.3 第 5 条、§18 合成失败边界、§19.1 第 10—11 项和 §20.3—5。

## 实施范围

### 创建

- `Tools/Luban/DataTables/Datas/合成规则_SynthesisRule.xlsx`：`TbSynthesisRule`，以 `inputTier` 为键，记录 `successRate` 与 `failureInkReward`。
- `Tools/Luban/DataTables/Datas/合成产物_SynthesisReward.xlsx`：列表表 `TbSynthesisReward`，按 `outputTier` 与 `spellType` 记录 `isOpen` 与 `weight`。

- `Assets/Game/Scripts/Runtime/Modules/SpellSynthesis/SpellSynthesisSystem.cs`：唯一公开入口。
- `Assets/Game/Scripts/Runtime/Modules/SpellSynthesis/SpellSynthesisProcedure.cs`：一次二合流程。

### 修改

- `Tools/Luban/DataTables/Datas/__tables__.xlsx`：登记两张表。

### 不涉及

- 不修改法术资产 Store Data，不创建合成 Store，不保存成功失败历史。
- 不显示 Tip、动画、概率或候选产物。

## 角色与职责

| 类型 | 所属模块 | JulyArch 角色 | 职责 | 必要协作 |
|---|---|---|---|---|
| `SpellSynthesisSystem` | 法术合成 | System | 创建并运行一次合成 Procedure | `SpellAssetSystem`、`IConfigSystem` |
| `SpellSynthesisProcedure` | 法术合成 | Procedure | 校验、随机、选择产物并完整提交 | 两张 Luban 表、资产 System |
| `SpellSynthesisRejectedEvent` | 法术合成 | 业务事实 | 携带两个实例 ID 与稳定拒绝原因 | 主界面 Tip |

## 状态与数据

无长期状态。`SynthesisRejectReason` 精确为 `SpellNotFound = 0`、`SameInstance = 1`、`DifferentTier = 2`、`Locked = 3`、`Equipped = 4`、`HighestTier = 5`、`Cultivated = 6`；`SynthesisOutcomeKind` 精确为 `HigherTierSpell = 0` 与 `MagicInk = 1`。随机值与当次产物只存在于 Procedure 生命周期。

## 行为与公开能力

| 类型 | 准确公开签名 | 语义 | 返回与失败处理 |
|---|---|---|---|
| `SpellSynthesisSystem` | `public UniTask<bool> TrySynthesizeAsync(long firstSpellId, long secondSpellId, CancellationToken ct = default)` | 完成一次二合 | 普通非法输入在责任位置记录日志、发布拒绝事实并返回 `false`；完整提交后返回 `true` |
| `SpellSynthesisRejectedEvent` | `public SpellSynthesisRejectedEvent(long firstSpellId, long secondSpellId, SynthesisRejectReason reason)`；只读属性 `FirstSpellId`、`SecondSpellId`、`Reason` | View 映射轻量 Tip | 不携带本地化文本 |
| `SpellSynthesisResolvedEvent` | `public SpellSynthesisResolvedEvent(SynthesisOutcomeKind kind, SpellType rewardSpellType, int rewardTier, int inkReward)`；只读属性 `Kind`、`RewardSpellType`、`RewardTier`、`InkReward` | 真实业务结算结果 | 非适用字段保持类型默认值，不代表操作失败 |

Procedure 在全部可恢复失败判定结束后才调用一次 Unity 主线程随机源；同一个 `[0, 1)` 单位随机值先判断成功，成功分支再按成功区间归一化并用于权重抽取，因此一次请求只消耗一个随机值。配置读取直接使用 `GetTable<T>()`，不预巡检 Luban 内容。

## Luban 配置

`TbSynthesisRule` 作者源字段固定为 `inputTier:int`、`successRate:float`、`failureInkReward:int`，首版行固定为：

| `inputTier` | `successRate` | `failureInkReward` |
|---:|---:|---:|
| 1 | 0.7 | 10 |
| 2 | 0.4 | 30 |

`TbSynthesisReward` 作者源字段固定为 `outputTier:int`、`spellType:SpellType`、`isOpen:bool`、`weight:int`，在 `__tables__.xlsx` 中使用 `mode=list`。首版二阶、三阶各包含 `Fireball`、`ChainLightning`、`FrostRing`、`Shield` 四行，全部 `isOpen = true`、`weight = 1`；三阶投入不建立合成规则行。

## 验收标准

- 六项合法条件全部由合成模块唯一判定；非法请求不调用随机、不修改资产。
- 成功与失败各只有一次资产原子提交，提交后发布唯一结算事件。
- 无 Store、保底、历史、Result 包装或 UI 代码。
- 作者源可生成，代码编译通过，不创建测试。
