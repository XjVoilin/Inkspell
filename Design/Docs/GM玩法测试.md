# GM 玩法测试

使用 July.Diagnostics 的 GMSystem、GMCategory、GMCommand 和 TMP 悬浮面板。桌面平台已启用 JULYGF_DEBUG；其他平台测试时在该平台的 Scripting Define Symbols 中添加 JULYGF_DEBUG。与 GooseMarket 相同，GM 命令、注册和调试扩展统一由 JULYGF_DEBUG 控制；不需要 GM 的构建移除此宏。

从 Launch 运行，进入主界面后点击左侧 GM 悬浮球，选择“法术”或“战斗”。

## 代码位置

- `Assets/Game/Scripts/GM/SpellGM.cs`：法术、合成与墨水命令。
- `Assets/Game/Scripts/GM/BattleGM.cs`：战斗测试命令。
- `HotUpdateRegistrar.RegisterGMCommands()`：集中注册两个命令类；游戏启动完成后构建框架面板。
- `GM/*.GM.cs`：同程序集的调试 partial 扩展，集中存放材料注入与合成结果控制，关闭宏后不编入。
- `GM/Game.Runtime.asmref`：Inkspell 的 asmdef 位于 `Scripts/Runtime`，此引用确保 `Scripts/GM` 仍属于热更运行时程序集，而非默认的 Assembly-CSharp。
- `GM/GMPanelLayout.cs`：当前 diagnostics 包的布局兼容适配，仅负责布局，不注册或执行业务命令。

使用实际配置枚举 `cfg.SpellType`，不再单独维护一套 GM 法术枚举。

## 操作

- 添加一对法术：选择类型与阶级，加入两张 1 级、未锁定的同阶法术；需要至少两个空位。
- 下一次必定成功 / 下一次转为墨水：仅覆盖下一次合法合成；无效拖放不会消耗设置；生效后自动恢复随机。
- 恢复正常随机：取消尚未消费的指定结果。
- 添加魔法墨水：默认 1000，用于点击卡片打开详情后测试培养。
- 装备四种法术：装备一阶火球、雷链、冰环、护盾，原装备移回合成区；预先要求至少四个空位，空间不足时不改变任何装备。

将一张法术拖到另一张同阶法术上进行合成。最高三阶、已锁定、已培养或已装备的法术仍按正式规则拒绝合成。GM 添加的材料、墨水及装备变化会保存到当前存档；不会删除或重置原有法术。

建议测试：添加两张一阶 → 指定成功 → 拖放合成 → 检查二阶产物和影子清理；再次添加一对 → 指定转墨水 → 拖放合成 → 检查材料消耗和墨水增长；补充墨水后点击法术测试培养；装备四种法术观察不同施法与命中表现。

战斗表现读取已提交事实：火球飞行时长来自真实攻击行程，施法与命中分开；雷链连线、冰环扩散与护盾展开各有不同动作。敌人带有行进轻动效、受击变形与闪色、TMP 实际伤害数字、死亡旋转缩小淡出。特效池上限 24，切换挑战时清理；画面不推进战斗逻辑或使用业务随机数。
