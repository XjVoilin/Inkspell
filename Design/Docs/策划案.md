本文只描述首个可玩验证版。它的任务是验证核心循环是否成立，不承担完整商业上线、长线运营和正式付费系统设计。

---

## 2. 产品概述

### 2.1 一句话介绍

玩家挂机获得低阶法术，在下方区域进行概率二合；合成成功获得随机高一阶法术，失败获得魔法墨水；墨水用于培养指定的单张法术。玩家把法术装备到活体魔法书上，在上方观看魔法书自动推关。

### 2.2 核心体验

```text
挂机积累低阶法术
        ↓
上线集中整理与二合
        ↓
成功：获得随机高阶法术
失败：获得魔法墨水
        ↓
升级或替换指定法术
        ↓
上方战斗能力立即变化
        ↓
通过原本失败的关卡
        ↓
提高后续挂机生成效率
```

### 2.3 设计目标

1. 玩家无需操作上方战斗，也能清楚看出法术成长带来的变化。
2. 合成成功提供短期跃迁，合成失败提供稳定培养资源。
3. 下方合成是主要操作，上方战斗负责验证数值与表现。
4. 首版保持简单，不提前加入流派、羁绊、活动和复杂商业系统。
5. 全部视觉资源应能通过图像生成、程序动画、粒子和 Shader 完成，不依赖大量人物逐帧动画。

### 2.4 非目标

首个可玩验证版不追求：

- 完整商业上线内容；
- 大量关卡和长期数值；
- 复杂策略战斗；
- 高质量人物动作和剧情演出；
- 通过格子容量制造付费压力；
- 与参考产品完全相同的题材、数值、美术或内容表达。

## 3. 屏幕结构

游戏采用 2D 竖屏布局，主界面同时展示战斗与合成。

```text
┌────────────────────────┐
│ 上方：横向自动推关                   │
│ 魔法书在左，怪物从右向左逼近         │
├────────────────────────┤
│ 中部：4 个已装备法术槽               │
├────────────────────────┤
│ 下方：6×4 法术整理与二合区域         │
│ 待领取法术独立累积，不受格子容量限制  │
└────────────────────────┘
```

建议首版比例：

- 上方战斗区：约 50%；
- 装备槽与关键状态：约 10%；
- 下方合成区：约 40%。

具体比例由 UI 实际可读性调整，不作为玩法硬规则。

## 5. 上方自动战斗

### 5.1 战场形式

- 固定 2D 侧视角；
- 活体魔法书位于画面左侧；
- 怪物从右侧生成并向左移动；
- 战场只有一条主要地面路径，首版不做纵深、多路线和地形机关；
- 四个已装备法术按照自身冷却自动释放；
- 玩家不控制移动、瞄准和施法时机。

### 5.2 目标选择

首版统一采用最简单规则：

> 法术默认选择距离魔法书最近的合法目标。

具体法术可改变目标数量或作用范围，但首版不加入复杂仇恨和目标优先级设置。

### 5.3 通关与失败

- 每关包含固定数量的怪物；
- 消灭当前关全部怪物即通关；
- 通关后自动进入下一关；
- 怪物抵达魔法书后持续攻击；
- 魔法书生命归零即挑战失败；
- 失败后短暂停顿并自动重试当前关；
- 首版不设置战斗超时、体力、门票和手动开始按钮。

### 5.4 战斗与合成并行

- 上方战斗持续运行时，玩家可以在下方整理、合成、升级和换装；
- 更换或升级法术后，上方从下一次合法施法开始使用最新数据；
- 首版不因合成操作暂停战斗；
- 首版不让上方敌人、伤害或异常状态侵入下方格子。

### 5.5 首版敌人

| 敌人 | 行为 | 验证目的 |
|---|---|---|
| 普通墨灵 | 标准生命、标准移速 | 验证基础输出 |
| 迅捷墨灵 | 低生命、高移速 | 验证减速与快速击杀 |
| 厚墨精英 | 高生命、低移速 | 验证持续输出 |
| 首章 Boss | 高生命、较高攻击 | 验证整体配装和生存 |

首版不加入远程敌人、召唤、护盾、分裂、治疗和控制免疫。

## 6. 首版法术

### 6.1 法术实例

每一张法术均为独立实例，至少包含：

- 法术定义；
- 阶级；
- 等级；
- 是否装备；
- 是否锁定；
- 唯一实例标识。

“阶级”来自合成，“等级”来自魔法墨水培养，两者相互独立。

### 6.2 四种法术

| 法术 | 首版行为 | 主要表现 |
|---|---|---|
| 火球 | 对最近目标造成单体伤害 | 朱红/橙红墨水弹道与命中爆散 |
| 雷链 | 命中后跳跃至附近目标 | 蓝紫色折线电弧与连续闪光 |
| 冰环 | 对一定范围造成伤害并减速 | 青蓝色墨水圆环、冰晶与染色 |
| 护盾 | 为魔法书提供临时护盾 | 暗金符文环与吸收闪光 |

### 6.3 阶级

首版设置三个阶级。阶级提升主要影响：

- 基础数值；
- 品质边框与角标；
- 特效尺寸、亮度或粒子数量；
- 必要时增加少量行为参数，例如雷链跳跃次数。

首版不为每个阶级重新设计一套完全不同的法术图标和效果。

### 6.4 重复装备

首版暂定允许同名法术重复上阵，以减少额外限制并方便验证数值。是否限制重复装备属于后续配装策略，不属于当前核心规则。

## 7. 自动生成与待领取

### 7.1 自动生成

- 系统按照生成间隔持续产生一阶法术；
- 产物从当前开放的四种法术中随机选择；
- 战斗在线和离线期间均可生成；
- 推关进度可以提高生成效率；
- 首版只自动生成一阶法术，不直接生成高阶法术。

### 7.2 待领取区

自动生成与可见合成格解耦：

```text
自动生成器
→ 待领取数量累积
→ 合成区存在空格时自动补入
→ 合成区满时只暂停补入，不暂停生成
```

格子容量不作为卡点：

- 首版不出售格子；
- 不设计格子解锁；
- 不因格子已满损失当前挂机周期内的产出；
- 离线收益通过累计时间上限控制，而非通过格子数量控制。

### 7.3 离线计算

至少保存：

- 上次退出或切后台时间；
- 当前生成间隔；
- 离线累计上限；
- 待领取法术数量。

重新进入时根据时间差计算新增待领取数量。具体离线上限属于可配置数值，首版不在策划案中锁定。

---

## 8. 二合系统

### 8.1 操作

玩家将一张法术拖到另一张同阶法术上发起二合。

首版条件：

- 两张法术阶级相同；
- 两张法术均未锁定；
- 两张法术均不处于已装备状态；
- 两张法术不要求同名。

### 8.2 结果

```text
任意两张同阶法术
        ↓
成功：随机获得一张高一阶法术
失败：两张法术消失，获得魔法墨水
```

- 成功产物从高一阶当前开放法术池中随机选择；
- 当前版本不对图鉴中未获得法术提供额外权重；
- “未获得优先”“重复保护”等属于后续策略，可由配置权重扩展；
- 最高阶法术不可继续合成。

### 8.3 成功率与保底

- 成功率按照输入阶级配置；
- 低阶可以设置为必定成功；
- 高阶允许失败；
- 每次失败可以提高该阶下一次成功率；
- 达到配置的保底条件后必定成功；
- 成功后重置对应阶级的保底进度。

首版的具体概率、递增幅度和保底次数在数值验证阶段确定，不在本文锁死。

### 8.4 已培养法术参与合成

首版采用最简单策略：

- 输入法术及其等级被消耗；
- 成功产出的高阶法术从 1 级开始；
- 已投入墨水不自动返还；
- 已培养法术发起合成前必须明确提示培养损失。

以下均属于未来可替换策略，首版不实现：

- 全额返还墨水；
- 按比例返还；
- 继承较高等级；
- 继承部分培养进度；
- 免费或付费重置。

---

## 9. 魔法墨水与单件升级

### 9.1 资源定位

魔法墨水是首版唯一培养资源：

- 主要由合成失败产生；
- 不绑定火球、雷链、冰环或护盾；
- 不区分阶级和类型；
- 由玩家选择具体法术实例进行投入；
- 不设置钱币作为中间消耗。

### 9.2 升级

- 每次升级只强化选中的单张法术；
- 升级消耗随法术阶级和当前等级增长；
- 升级提高该法术的主要数值；
- 等级上限、成本和成长曲线均由配置决定；
- 首版不做全局科技、流派等级和账号永久属性树。

### 9.3 升级反馈

```text
选择一张法术
→ 墨水从资源区域流向法术
→ 图标短暂放大与发光
→ 等级数字更新
→ 上方后续施法使用新数值
```

## 10. 装备系统

- 首版提供四个装备槽；
- 玩家可将合成区中的法术拖入装备槽；
- 已装备法术不占用可见合成格；
- 替换后的旧法术优先回到空格，格子已满时进入待领取/暂存状态；
- 上方战斗始终读取当前四个装备实例；
- 首版不做流派、羁绊、套装、职业限制和自动配装。

未来增加槽位或配装规则时，不应要求修改合成核心。

---

## 11. 关卡与挂机效率

### 11.1 关卡

首版十个测试关卡只用于形成数值墙：

- 前几关验证基础火球；
- 中段加入迅捷怪，验证冰环减速；
- 后段增加敌人数量，验证雷链；
- Boss 关同时验证输出和护盾。

### 11.2 推关收益

推关至少影响一项挂机参数，例如：

- 缩短基础法术生成间隔；或
- 提高单位时间生成数量。

首版只选择一种最容易理解的增长方式，避免同时引入多条收益公式。

## 12. 视觉与表现

### 12.1 已确认风格

> 明亮纸张底色＋粗描边剪纸角色＋彩色墨水法术。

### 12.2 视觉规则

- 背景使用暖白或浅色纸张，减少高对比装饰；
- 魔法书和怪物采用清楚的深蓝/黑色粗描边；
- 怪物使用侧视剪纸形态；
- 火球使用橙红墨水；
- 雷链使用蓝紫墨水；
- 冰环使用青蓝墨水；
- 护盾使用克制的暗金符文；
- UI 文本由 Unity 字体渲染，不生成在位图中；
- 合成格和法术图标优先保证小屏可读性。

### 12.3 程序化表现

角色和怪物首版不制作复杂逐帧动画，主要使用：

- 位移与缓动；
- 压缩与拉伸；
- 受击闪白；
- 轻微震动；
- 墨水溶解 Shader；
- 粒子、拖尾和 LineRenderer；
- 通用死亡墨滴效果。

### 12.4 必做表现

1. 火球飞行与命中；
2. 雷链多目标跳跃；
3. 冰环扩散、减速与碎裂；
4. 护盾生成与吸收；
5. 合成成功；
6. 合成失败化为墨水；
7. 单件升级；
8. 怪物受击与死亡；
9. 通关与失败。

## 15. 数值配置边界

以下数值必须配置化，但本文不提前定死：

- 各阶合成成功率；
- 失败后成功率增量；
- 保底次数；
- 失败墨水数量；
- 法术升级成本；
- 法术等级上限；
- 法术基础伤害、冷却、范围和持续时间；
- 怪物生命、攻击和移动速度；
- 生成间隔；
- 离线累计上限；
- 关卡对生成效率的提升；
- 合成产物随机权重；
- 上阵槽、格子、阶级和内容数量。

“可配置”不等于首版制作复杂后台或热运营系统，只要求数据与固定流程分离。

## 16. 合成规则的实现边界

合成规则使用策略接口隔离，但首版不为假设需求增加工厂、运行时 Setter 或测试专用构造入口。

约定：

- `SpellMergeSystem` 持有 `ISpellMergeRules`；
- `SpellMergeSystem` 在初始化时直接创建当前规则实现；
- 首版实现为 `V1SpellMergeRules`；
- 策略负责判断和结果计算；
- System 负责读取状态、执行消耗、发放结果、更新保底和发布事件；
- 后续策划改变规则时，新增规则实现，并修改 System 初始化中的创建代码；
- 只有出现多规则并存、活动切换或 AB 测试等真实需求时，才增加进一步装配结构。

首版不实现流派和羁绊的空壳系统，只保证数量和内容不在战斗、合成和 UI 中写死。

## 18. 验证标准

首个可玩版本完成后，重点回答以下问题：

1. 玩家是否能在不解释复杂规则的情况下理解“同阶二合”？
2. 合成成功是否产生足够明显的跃迁感？
3. 合成失败获得墨水后，玩家是否仍愿意继续合成？
4. 升级或换装后，上方战斗变化是否立即可见？
5. 自动失败、重试、变强、通关的反馈链是否顺畅？
6. 玩家是否愿意连续进行“生成—整理—合成—升级—推关”循环？
7. 明亮纸张、剪纸角色和彩墨法术在真机小屏上是否清楚？
8. 基础特效在目标设备上是否保持稳定帧率和可接受的透明叠加开销？

验证版的成功不以关卡数量和收入为标准，而以核心循环是否值得继续扩展为标准。

- 流派标签与 4＋2 羁绊；
- 未获得法术权重和重复保护；
- 培养返还、等级继承和重置；
