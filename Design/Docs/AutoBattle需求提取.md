# AutoBattle 需求提取

日期：2026-09-07。状态：需求已提取，首轮实现与 21 项自动测试已完成；用户确认项和实施暂定项如下区分。

## 1. 来源与方法

先提取玩家规则、状态生命周期、外部协作和验收结果，再设计角色。只使用 [GDD](GDD.md) 和 [策划案](策划案.md) 的产品需求，不使用业务源码、测试、模块设计或 MDD 推导需求。

GDD 日期为 2026-08-27，比策划案更新且明确细化版本范围，冲突时本轮采用 GDD。用户补充优先于文档：**应用未退出时切回前台继续原挑战，后台经过的时间不计入战斗；换装保留槽位剩余冷却，新挑战所有槽从就绪开始；无敌人时护盾等待。**

需求不预设类名、目录、框架角色、模拟频率、算法或事件形式。设计建议与未决项不属于已确认需求。

## 2. 产品目的与范围

自动战斗是玩家成长的持续验证场：玩家在下方生成、合成、升级和换装，上方展示伤害、控制和生存变化，形成失败、变强、重试、通关的反馈循环。玩家无需操作开战、移动、瞄准或施法。

本次分析覆盖单次挑战、连续挑战衔接、战斗显示及与长期进度和装备的关系。法术获得、合成消耗、升级成本与离线产出计算属于相邻业务。

| AB-03 | 敌人种类、数量、出场顺序和时机按关配置；四类敌人以生命、移速、攻击等差异验证配装 | §5、13、17.4 |

| AB-09 | 种类、阶级、等级影响施法能力；等级仅提升伤害或护盾主要数值，不改变冷却、范围、连锁数、持续时间、减速参数 | §7.3、11.2 |

| AB-15 | 首版最大第 10 关，通关后重复第 10 关，不进入不存在的下一关，不继续增加进度或生成效率 | §4.3、20.9 |
| AB-16 | 新挑战从关卡起点完整重建；敌人、书生命/护盾、攻击、效果、冷却和已消灭数量不继承 | §6.3、14.2 |

| AB-18 | 重新启动恢复最高关、法术实例和装备，从当前关起点新开挑战；战况不持久化；离线只计算法术生成收益 | §14.1—2、18、20.12 |

## 4. 数据生命周期

| 数据 | 业务生命周期 | 战斗使用方式 |
|---|---|---|
| 最高关进度 | 跨启动保留 | 开局确定关卡，获胜后在上限内推进 |
| 法术实例、装备、等级 | 跨启动保留，玩家操作可改变 | 每次合法施法使用最新能力 |
| 关卡、敌人、法术配置 | 内容定义 | 决定规则与数值，不是玩家战况 |
| 挑战身份、出生进度、书、敌人、冷却 | 一次挑战 | 随战斗变化，重试或重进时重新建立 |
| 已发攻击的生效依据 | 施法发起至命中或消失 | 不被后续装备变化追溯修改；目标如何确定见 Q-04 |
| 护盾、减速及范围效果 | 生效至过期或挑战结束 | 按业务规则持续，不因换装立即撤销 |
| 本次胜负及结果反馈 | 终局至结果停顿结束 | 决定重试/下一关，并给出清楚反馈 |
| 动画、粒子、音效播放状态 | 一段表现期间 | 表达业务事实，不决定业务命中或胜负 |

整局重建与下一次施法读取最新装备是不同时间尺度，不能用开局固定全部装备数据替代后者。

## 6. 需求验收

1. 新玩家无需操作即开始初始火球战斗；其他空槽不影响运行。
2. 选敌遵循最近合法目标；空场但仍有后续敌人不会通关。
3. 四种法术分别显示单体、多目标、范围减速与护盾效果；护盾重施不累计相加。
4. 同名法术分占两槽独立施法；换装、升级不中断战斗，已发攻击保持原来生效数值。
5. 最后敌人同时具备攻击机会和致死命中时，按命中优先获胜。
6. 失败停顿后同关完全重建；胜利停顿后进入下一关；最大关保持重复。
7. 切后台再返回继续原局且不补算后台战斗；退出再启动则恢复资产与最高关、重新开局。
8. 下方操作时仍能清楚观察战斗反馈；表现播放不改变命中与胜负的业务时机。

新增 AutoBattleFlowTests 覆盖上述主要流程，连同局部规则测试共 21 项通过。模拟频率、类数量和文件布局不作为玩家验收条件；真机表现性能仍需目标设备验证。
